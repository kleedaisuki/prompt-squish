# IR persistence: borrowed projections and streaming identities

Date: 2026-10-01. Status: implementation and focused tests prepared; hosted compilation,
regressions, and allocation measurements are required before claiming verified performance.
Related: [core mechanisms](v1.2-core-mechanisms.md), [archive mechanisms](v1.2-archive-mechanisms.md),
and [IR model](../design/ir-model.md).

## Mechanism and repair

The v1.2 container intentionally stores a stripped semantic unit and a complete debug unit.
Its wire contract therefore repeats semantic arenas. This repair preserves that contract;
it removes temporary repetitions rather than inventing a smaller, incompatible format.

Previously `encode_unit_container` cloned the complete unit, cleared debug fields in the
clone, materialized both payloads, and copied them into a final container. Section hashing
constructed another payload-sized vector, and the custom SHA-256 implementation constructed
both a framed message and a padded message. Decode copied section bodies and again cloned
and serialized the complete semantic projection merely to compare it.

The canonical unit writer now has bounded sinks for counting, final-buffer output, streaming
SHA-256, and byte-for-byte comparison. Semantic and full projections borrow the same arenas.
Counting visits strings by length, not content. The final container is allocated exactly once
and both unit sections are appended directly to it. Directory checksums hash slices of that
final buffer. Semantic/source/producer stripping remains exactly the former wire projection.
The empty source digest is initialized once, outside repeated projection work.

Typed decode uses a validated borrowed section directory. All former container checks remain:
magic/schema/kind/flags, ordered tags, contiguous offsets, integer bounds, supported digest,
per-section checksum, descriptor decoding, critical-extension policy and exact exhaustion.
The complete debug unit still undergoes bounded canonical decoding and structural validation.
Its semantic projection is compared directly with the semantic section using bounded slice
comparisons, without a payload-sized second serialization. Comparison rejects extra bytes,
missing bytes, and semantic differences even when the attacker recomputes valid checksums.
The public owning `decode_container` retains its owning contract and materializes sections only
when callers specifically request ownership.

## Identity and portable metadata APIs

`Digest::sha256`, section digests and container partition digests use RustCrypto `sha2` 0.10,
already present in the lockfile, through its incremental API. No new custom cryptography,
CPU-specific compile flags, or unverified hash algorithm is introduced. Domain framing remains
`xmlsquish\0` + UTF-8 domain + zero + exact message. Object digest hashes the canonical directory
and borrowed payloads, not a reconstructed complete container.

`UnitEncodingOverrides` borrows defining source, import declarations, source-key relocation map,
and producer metadata. Source maps affect header identity, source records and source attachment;
source line tables, strings, operations, regions and definitions are never cloned. A supplied
header source is the final identity and must agree with the mapped original attachment identity.
Import substitutions must preserve local IDs and expected kinds and satisfy existing spec rules.
Only identities consumed by this unit are checked: repeatedly walking an entire global source
map for every unit would introduce the quadratic behavior this work is meant to remove.

`VerifiedUnitEncoding` is an immutable borrowed proof constructed by complete validation once.
Its encoding and semantic-digest methods validate only each metadata substitution, so SOPack
seed/output passes do not repeat arena validation. The type cannot be constructed unchecked,
and its borrow prevents the original unit from changing while the proof is in use.
Its `object_digest` method derives the exact complete container identity without constructing
container or unit payload bytes: count both projections, stream their section checksums, write
only the fixed 194-byte directory on the stack, then stream directory, descriptor and both
projections into the object domain. This allows the sealed compiler preparation boundary to
derive actual semantic/object identities rather than trusting caller-supplied digest labels.
The multiple immutable hash traversals are preparation work, not repeated per link or invocation.

`encode_unit_container_with` writes the projected complete container. The ordinary encoder
uses the default empty overrides. `semantic_unit_digest_with` streams exactly the semantic
partition digest directly from the borrowed projection. SOPack seed construction can use this
identity without building and then decoding a throwaway complete unit container. Final portable
unit publication uses the complete projected encoder once.

## Sealed pipeline witness

`ValidatedUnit` owns shared immutable IR plus an internally derived `UnitRevision` and
`DebugDigest`. Its private fields cannot be forged by callers. `new(Arc<RelocatableUnitIr>)`
validates raw IR once and streams its canonical identities. `decode(&[u8])` performs one
borrowed container verification, one typed decode/validation and semantic projection equality;
it computes identities from actual validated slices, without re-encoding or a second decoder.
Its `encode()` reuses the structural proof. Compiler preparation consumes the witness rather
than trusting claimed digest labels or repeating the validation/hashing pipeline.

The legacy decoder already accepts future minor versions and optional noncritical debug
sections. A decoded witness preserves the minor and those optional extension payloads, and
therefore `encode()` preserves its actual object/debug identity rather than claiming that any
accepted raw container equals the canonical three-section writer. Known IR payloads are never
copied to retain extensions. The normal writer path has no extension allocation. The exceptional
extension encoder also borrows both IR projections into a single final allocation; only actual
unknown extension payloads are retained in shared ownership.

## Verification contract

Focused tests include:

- An independently retained test-only legacy writer that owns and strips the debug clone,
  then builds the former section layout. Its bytes must equal the new writer for Module,
  Entry, Pack and Sopack, including a multi-megabyte Unicode string and independent Sopack root.
- Decode round trips and exact semantic/object identity agreement for all four kinds.
- Borrowed source/import/producer substitutions equal an actual owned metadata rewrite.
- Checked debug payloads whose semantics differ from a valid semantic section are rejected;
  appending to the semantic payload remains rejected even with valid container checksums.
- SHA-256 known vectors and framed incremental hashing across 55/56/63/64/65-byte and larger
  boundaries, using multiple segment widths.

Existing core encode/decode and archive large-IR allocation axes are the primary measurements.
A streaming semantic-digest control should allocate only bounded metadata and validation work,
not bytes proportional to the large string payload. Counting allocations is a separate run from
normal-allocator latency. A timing improvement is not inferred from removed copies alone.
Published v1.2.0 tag and assets remain unchanged; no local Cargo/npm operation is permitted for
this work because the user's disk and compute are constrained.

## External grounding and limits

The mature implementation choice follows [RustCrypto sha2 0.10.9 documentation](https://docs.rs/sha2/0.10.9/sha2/):
its incremental `update` / `finalize` contract avoids concatenating independently available
slices. We preserve SHA-256 and domain separation, rather than replacing integrity validation
with a faster but weaker checksum.

The academic measurement constraint follows Mytkowicz et al., ASPLOS 2009,
[Producing Wrong Data Without Doing Anything Obviously Wrong!](https://www2.ccs.neu.edu/racket/Performance/mytkowicz.pdf):
layout and experimental setup can bias apparent optimizations. Therefore structural allocation
scaling and same-workload byte/digest oracles complement paired timing. Repeated samples alone
are not interpreted as proof against setup bias. This is an engineering repair, not a claim of
novel hash, serialization or compiler research.

The unchanged dual-payload v1 format still imposes two final copies of semantic content. Removing
that inherent distribution cost would require a separately versioned wire schema and migration;
this repair does not silently alter already established persistent identities.
