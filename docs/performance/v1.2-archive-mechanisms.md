# v1.2 archive mechanisms: source audit and in-process probes

Date: 2026-10-01. Branch: `codex/v1.2-mechanism-benchmarks`.
Status: source-derived models and runnable measurement design; hosted results pending.
No production code, v1.2 tag or published release is changed by these probes.
This is an audit of v1.2 itself, not a v1.1 speed comparison.

## Evidence boundary and reused knowledge

Read alongside [the archive contract](../design/v1.2-archives.md),
[the naivety review](v1.2-naivety-review.md), and
[historical source overheads](v1.2-source-overheads.md). Existing process-level
measurements cannot isolate normalization, canonical reader verification, ownership
copies or provider graph rounds. Their absolute CLI costs are not substituted for
the mechanism observations below.

The probes invoke shipping `squish_backend::archive` public APIs, not algorithm
imitations. There is no benchmark-only public production API. Private manager
costs are explicitly source evidence: a backend payload clone is not a measured
manager stage, and a writer control is not an isolated reader parsing phase.

Notation: N = ZIP members; D = unique stored member content bytes; B = full archive
bytes; L = total path bytes; U = module units; P = owned IR bytes; G = exact provider
groups; E = frozen import edges; F = asset bindings; a = one shared asset's bytes;
A = expanded asset bytes (`F*a` for fanout fixtures).

## Predictive source models

| Shipping mechanism | Necessary work | Current repeated work and prediction |
| --- | --- | --- |
| `write_reproducible_zip` | CRC and write each stored byte; validate names; emit N local/central records. | Borrows member bodies, but sorts a reference vector, allocates lowercase-name set and a growable central buffer, then copies the central buffer into the reserved output. Expected O(D + L + N log N), with path-depth prefix-set lookup factors; allocated bytes include B plus central-directory capacity and name metadata. A member-count slope at fixed D is not a byte-copy slope. |
| `read_reproducible_zip` | Bounds/CRC/path checks; complete canonical metadata and local/central agreement. | Copies all D member bytes and reconstructs a complete B-byte archive with the writer solely for byte equality. CRC traverses D again. Peak delta above the prebuilt input baseline contains owned members plus canonical output/directory, approximately D+B plus metadata, not merely D. Rebuild is intentional strict validation, not an accidental second returned product. |
| `write_sopack` | Validate exact source identities/closed bindings; normalize/encode portable units; deduplicate asset blobs; output ZIP. | `portable_paths` clones, normalizes and encodes every unit to seed fingerprints; output assembly clones, normalizes and encodes it again. Source bytes are cloned into member staging; unique assets are cloned once into staging. Every F binding separately hashes its asset bytes even if disk content is shared, in addition to provider seed hashing. Predictions: O(P + source bytes + A) byte work before graph/ZIP cost, with repeated full-IR serialization and copies. |
| `portable_paths` graph colors | Stable identities independent of host checkout and frozen reference topology. | Exactly G rounds even for edgeless providers. Each round builds a fresh map, visits all G groups, builds/sorts outgoing descriptors and hashes each edge. Source-derived work is G² group visits and G*E edge visits, plus BTree/string lookup and per-group sorting: O(G*(G log G + E log G + sum d_g log d_g)) metadata work. No convergence check exists. This is not presented as a measured quadratic slope until fixed-data rows establish it. |
| `read_sopack` | Strict ZIP read, canonical manifest, exact digests, IR decode and source relocation. | Shared asset blobs remain in `files` while each owner receives a new Vec; each binding hashes the same shared blob again. Peak delta includes expanded A plus unique decoded content and metadata. A small archive with high fanout can cost much more memory/CPU than its B suggests; default expanded-content and binding bounds remain essential. |
| `SopackPayload::clone` / `ArchiveEntry::clone` | An owned clone API must own its copies. | Deep-copy controls expose Vec/String/BTree ownership without normalization/hash/ZIP work. They do not model a borrowed/Arc replacement or prove that a manager stage spends the same time. Returned owned copies are destroyed inside measurement. |

The reader canonical-writer control uses the exact already-decoded members, so it
measures the actual shipping reconstruction operation. `strict_read - rebuild`
is **not** reported as an exact parse time: allocator reuse, destruction, live
working sets and separate batches prevent an additive causal interpretation.
There is no permissive reader baseline that silently drops canonical checks.

## Fixed-data workload matrix

All fixture construction, source digests, encoding for counters, assertions,
allocation self-checks, warmup and JSONL formatting are outside measurement.
Timings contain no filesystem/SQLite/process startup or compiler frontend work.

| Workload label | Varied axis (exact range) | Held fixed / reported confounders |
| --- | --- | --- |
| `zip_member_count` | N = 1, 8, 64, 512, 4096 | D = 4,194,304 bytes; equal-length `data/000000.bin` names, reversed producer order. B and directory bytes necessarily grow with N. |
| `zip_payload_bytes` | D = 0, 4096, 65,536, 1,048,576, 4,194,304, 16,777,216 | N = 32; same names and order. Bytes split exactly, including any remainder. STORED ZIP avoids compression-ratio/codec confounders. |
| `shared_asset_binding_fanout` | F = 1, 2, 8, 32, 128, 256 | U=G=1, E=0; one unique 65,536-byte blob; A=F*65,536; constant diagnostic attachment/IR. Distinct defining-source-relative binding spellings. Manifest/B grow slightly with F; physical blob does not. |
| `sopack_ir_ownership_bytes` | One unreferenced semantic string = 0, 4096, 65,536, 1,048,576, 4,194,304 bytes | U=G=1, E=F=0; diagnostic source=64 bytes. String is valid IR, not a frontend-generated macro body; this isolates owned/serialized IR byte work, not operation execution. |
| `provider_groups_isolated` | G = 1, 2, 4, 8, 16, 32, 64, 128 | U=128, source bytes=8192, E=0; same unit source paths and bytes; grouping only changes exact package identity partition. |
| `provider_groups_chain` | Same G | U=128, source bytes=8192, E=127; unit-level chain held fixed. |
| `provider_groups_star` | Same G | U=128, source bytes=8192, E=127; unit zero imports every other unit, fixed dense import header at root. |
| `provider_groups_cycle` | Same G | U=128, source bytes=8192, E=128; unit-level cycle held fixed; no DAG-only assumption. |
| `provider_tail_512_isolated`, `provider_tail_512_cycle` | G=U=512; E=0 or 512 | Separate long-tail labels, source bytes=32,768. Not part of fixed-U fits and not misrepresented as independent graph-only scaling. |

Graph fixtures keep original SourceKey serialized field widths, logical paths,
source attachment bytes and unit-level import declarations constant within a
topology. Distinct grouping is `(unit_index % G)`. Provider content differs by
its controlled unit paths/source bytes, preventing duplicate-content rejection
from shortcutting the algorithm. Normalized archive paths and resulting B
necessarily vary when units move out of the root group; actual `archive_bytes`
and `encoded_unit_bytes` are recorded rather than pretending exact output size is
constant. Minimal valid Module IR avoids conflating frontend/macros with transport.

Per row, JSONL records `members`, `content_bytes`, `name_bytes`, `archive_bytes`,
or `units`, `providers`, `graph_rounds`, `import_edges`, `source_bytes`,
`encoded_unit_bytes`, `asset_bindings`, `unique_asset_bytes`,
`expanded_asset_bytes`, `group_round_visits`, `edge_round_visits` as applicable.
**Graph rounds and visit dimensions are source-derived deterministic work
counters, not instrumented timings or sampled profiler events.** Allocator
counters are measured independently by the common tracking allocator.

## Ownership and allocation experiment contract

Files: `crates/squish-backend/benches/archive_latency.rs`,
`archive_allocations.rs`, and `workloads.rs`; shared harness:
`scripts/perf/mechanism_support.rs`. Opt-in Cargo feature:
`mechanism-benchmarks`; `autobenches=false` prevents shared fixture files becoming
accidental standalone benches. Both targets use `harness=false` and recognize
`--test` as bounded smoke (ZIP 8/64KiB, SOPack 4 units/2 groups/cycle, fanout2).

Latency binary uses the normal allocator. Allocation binary alone installs
`TrackingAllocator`, with live bytes tracked across fixture creation and a
baseline-subtracted peak per operation. Both execute the harness allocation
self-check before rows. Counters are requested layout bytes/calls, successful
reallocation/deallocation behavior and peak live delta, **not RSS**. Counting
timings must never be substituted for uninstrumented latency.

The harness black-boxes inputs/results; every operation returns a fresh owned
result and drops it **inside** timing/counting. Write operations borrow fixtures;
read operations borrow encoded bytes. The clone operations intentionally clone
inside measurement. No operation clones an input merely to reset a reusable
fixture. Reproducibility checks run producer encoding twice before measurement;
strict decode validates actual transport, source byte multisets and binding/unit
counts, and fanout bytes are checked exactly. Shipping corruption/truncation and
relocation tests remain authoritative semantic regressions.

Default harness: 2 warmups, 7 samples, adaptive batches targeting 10ms, capped at
1024 operations; allocations default one operation/sample. Hosted runs record
environment/profile/commit/raw rows and may lower bounded sample controls to fit
CI budget. No local Cargo/npm was run because of user disk/resource constraints.

Hosted reproduction (do not run locally in this workspace):

```sh
cargo bench --locked -p squish-backend --features mechanism-benchmarks --bench archive_latency
cargo bench --locked -p squish-backend --features mechanism-benchmarks --bench archive_allocations
```

## Manager source audit (not measured by these probes)

1. `archive_build::freeze_inputs`: each source searches locked package rows;
   `install_archive_source` then scans archive units until a logical path matches,
   and scans all asset bindings to select owner assets. For U sources from one
   library and M assets, upper-bound comparison work is O(U²+U*M), plus O(U*Q)
   locked-package search for Q locked packages. The payload itself is held in Arc,
   yet each selected unit and owned asset Vec is cloned into FrozenSource. Exact
   digest/attachment checks are safety work, not removable repeated overhead.
2. `archive_build::emit` clones the **whole** `state.compiled` map and resolution
   before selecting reachable library units. `sopack_bytes` clones selected units,
   sources and assets into a payload, after which the backend normalizes/copies
   again. Fixed tiny reachable output with unrelated project P increasing should
   expose unnecessary O(P) cloning; our backend clone rows alone cannot confirm
   that manager prediction. Relevant stage-owned source paths remain required.
3. `build::linked_for` clones LinkOutput on ordinary named lookup;
   `instantiated_for` clones both stored linked document and InstantiateOutput.
   Digest fallback lookups serialize/hash candidate outputs and clone again.
   These are real source ownership costs, not filesystem latency measurements.
4. The shipped IncludeIndex builds adjacency/revision references **once per
   pack**. Per-child projections clone only reachable snapshot evidence and IR,
   with cycle guards and canonical sorting. Its prior O(I*(U+E)) global scan was
   already fixed and is not listed as current. Distinct children still link their
   shared modules independently; repeated references to one entry memoize emitted
   bytes. A benchmark of this private path would require a narrowly private
   harness or a real manager invocation, not a duplicate toy graph implementation.
5. Pack members copy frozen asset/include bytes into owned ArchiveEntry, then
   writer copies into ZIP. This intermediate copy is avoidable with a new borrowed
   internal ownership design; the final named ZIP member writes are unavoidable.
   No ownership/public API change is made before evidence.

## Next discriminating interpretation

- Fit allocation bytes/peak against D at fixed N before proposing direct canonical
  validation; use member-count rows to reveal directory/set overhead separately.
- At fixed 128 units and fixed topology, compare write slope vs measured deep clone
  and strict-read slopes across G. A steep G-only write slope consistent with G²
  is graph-stage evidence, not merely a large-payload claim. Isolated graphs are
  the strongest test of rounds doing work without topology propagation.
- Hold unique asset bytes constant and compare write/read/clone costs against A.
  On-disk deduplication is not in-memory deduplication. A future shared-byte design
  needs explicit ownership/bounds and must preserve defining-source lookup.
- Measure manager private source hypotheses separately before prioritizing them
  against ZIP/graph costs; do not multiply a clone microbenchmark by guessed stage
  counts and report that as observed end-to-end savings.

## External grounding

[Reproducible Builds archive guidance](https://reproducible-builds.org/docs/archives/)
supports deterministic metadata/order, not dropping validation to make a bench
faster. [Valgrind DHAT's documentation](https://valgrind.org/docs/manual/dh-manual.html)
distinguishes allocation traffic/lifetime/peak concepts; our lightweight requested
layout counter is not a full DHAT/RSS profile. The peer-reviewed
[ICSE 2025 reproducible packaging study](https://www.cs.cmu.edu/~ckaestne/pdf/icse25_rb.pdf)
examines six package ecosystems and motivates byte-reproducible reusable libraries;
it does not validate any xmlsquish performance claim. These external constraints
favor explicit immutable ownership and preserved correctness boundaries while
testing repeated mechanical work, rather than permissive-reader comparisons.
