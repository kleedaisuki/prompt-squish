Scope: compiler/linker/archive/manager algorithms and immutable data ownership.

## Existing knowledge and evidence boundary

This review extends `v1.2-source-overheads.md`, `v1.2-pipeline.md`,
`../design/v1.2-middle-end.md`, `../design/v1.2-archives.md`, and the prior

Notation: B = encoded archive bytes; D = decoded unique content bytes; A = expanded
asset-owner bytes; G = distinct provider groups; E = frozen import edges; U = unit
count; P = total owned IR/debug/optimized-fact bytes; I = distinct included entries;
R = regions; O = operations; S = selected scalar bytes; K = invocation count.

## Fixed-data experiment design

- Archive decode: hold B constant while varying member count; separately hold count
  constant while varying B. STORED bytes avoid compressor variation. Include valid
  tiny, one large member, many tiny members, shared-asset fanout and corruption cases.
- Provider identities: run groups {1,8,32,128,512} across edgeless, chain, star and
  cycle topologies, reporting G,E and source/unit/asset bytes. A dense topology is a
  separate axis, not an unexplained larger fixture. Distinct providers must differ
  in one controlled field so duplicate-content rejection cannot shortcut work.
- Manager clones: fix reachable/output bytes while add unrelated unit payload and
  separately vary target/include count. Benchmark metadata indexing, payload clone,
  actual linking and emission separately. Keep mutation, validation and failure
  paths outside throughput samples but require semantic equality checks.
- Scalars: hold O and source bytes fixed while selected RenderText fraction varies;
  then hold selected body fixed and vary K. Compare per-call trace records, exact
  prompt bytes, scalar substitutions and identical budget rejection before timing.
- End-to-end consumers: large SOPack with a tiny reachable export, followed by a
  broad export, distinguishes startup/acquisition constants from closure expansion.
  A library microbenchmark that consumes every unit cannot expose eager loading.

## Measurement / allocator contract for emerging benches

Timing and allocation are different experiments. A tracking allocator's atomic
counters add per-allocation work; do not compare tracked latency to an untracked
baseline and call the difference production overhead. Both alternatives need the
same instrumentation, with uninstrumented timing also reported when practicable.

Build fixtures before the measurement reset. If live bytes are tracked, record the
live baseline L0 at reset and report peak delta `max_live - L0`; resetting `live=0`
while fixture allocations remain alive causes later deallocations to underflow.
A realloc must account for old/new layouts only on success; a failed realloc leaves
old ownership unchanged. Count requested layout bytes, distinguish cumulative
allocated bytes from peak live bytes and RSS, and include result destruction only
when explicitly part of the measured operation. Returning/dropping a decoded payload
is a different boundary from borrowing it; report the selected contract.

Use `black_box` for input and observed outputs, validate deterministic output once
outside timing, retain a digest/counter so the compiler cannot erase work, and state
whether input cloning is necessary API ownership or fixture setup. Fresh-owned-input
APIs require reconstruction each iteration; cloning inside the timed closure measures
that tax, excluding it measures only the callee. Both are informative but must not
be mislabeled. Avoid benchmarks whose constant output ignores dynamic fixture data.

Use paired/interleaved alternatives, warmup, enough repetitions and complete raw
samples. Independent GHA runs are necessary for stable conclusions. Compilation,
filesystem fixture creation, JSON report formatting and baseline downloads stay
outside operation timing. Absolute mechanism costs and normalized bytes/edges/ops
are primary; old-version CLI ratios are supplementary impact evidence.

## External reality and preservation constraints

The project research note already anchors immutable compiler objects in LLVM/ThinLTO
and archive metadata in Reproducible Builds guidance. Those practices favor immutable
shared objects and explicit validation boundaries, not removing checks for benchmark
wins. The peer-reviewed build-system and reproducible-packaging evidence in
`../research/pack-sopack-reproducibility.md` motivates declared immutable inputs and
full byte equality; it does not prove these candidate mechanisms faster.

Potential remedies must preserve portable source relocation, definition-site asset
ownership, exact snapshot/import evidence, archive memory bounds, deterministic ZIP,
public API input validation and output/provenance semantics. No unsafe pointer or
host-path shortcut is proposed. No production change or measured speedup is claimed
by this review.

## Additional hot-path mechanisms independently verified

### Origin lookup: highest-priority runtime scaling probe

`instantiate.rs::origin` performs `.position` over the entire unit OriginTable for
Operation, Region and Definition lookups. Emitted occurrences call `op_origin` when
recording SourceSpan; macro entry and frame creation resolve definition/call origins.
For Q dynamic lookups and H static origin entries, worst-case cost is Theta(Q*H),
with strong dependence on matching row position despite constant semantic output.
This can obscure the already-constant-time DefAddr lookup.

Use identical first/last macro bodies at fixed definition count D and expansion
count K; vary D with fixed K and K with fixed D. Verify equal prompt bytes while
retaining intentionally different source origins; do not assert equal source IDs.
A separate lookup-only probe must return the selected original OriginId and validate
it against `.position` before timing. The integrated evaluator includes provenance
work, so it answers whether the lookup mechanism matters to actual expansion.

Minimum future indexing design: per unit Operation/Region/Definition vectors sized
by the existing dense arenas, holding Option<OriginId>. Traverse original origin rows
once and fill only absent slots, preserving the current FIRST matching row. Validator
`validate_origins` checks operation coverage but permits duplicate `(EntityKind,id)`
rows; changing first-match semantics is not an optimization. Region/Definition origin
IDs are not fully arena-bounds-validated there, so never size a dense vector from a
malformed row's maximum local ID. Ignore irrelevant/out-of-range rows for indexed
lookup and retain existing region -> first operation fallback. Attach the unchanged
unit ObjectDigest to the selected local OriginId at lookup. No production fix before
measurement is proposed.

### Scalar-value interning: distinct-value quadratic probe

`instantiate.rs::intern_scalar` uses `.position` over `scalar_values` for every value.
K distinct argument/capture values require Theta(K^2) equality comparisons, while K
reuses of the first value are linear in K. A macro that ignores its scalar parameter
can keep emitted output fixed while varying distinct-value fraction and value size.
New-value arena population is necessary; rescanning every prior value is not. A future
string-to-ID index must preserve first-insertion IDs and retained provenance, not sort
or renumber the existing scalar arena. Measure comparisons/allocation separately from
source compilation and macro argument encoding.

## Common harness source-review checkpoint

`scripts/perf/mechanism_support.rs` now defines separate latency and allocation APIs.
Its ownership contracts are explicit: ordinary `latency` includes result destruction;
`latency_prepared` excludes preparation/result drop and times each owned call with an
Instant interval. The latter has a clock-read floor, so tiny mechanisms need a similarly
segmented no-op control rather than comparing directly to a batched borrowed control.

TrackingAllocator maintains all allocation lifetimes while inactive, preventing fixture
baseline underflow; failed allocations/reallocations do not alter live ownership, and
successful realloc updates old/new requested layouts. Counter reset occurs outside
operations; JSON printing happens after accounting stops. Operations must join/quiesce
threads at boundaries. Latency executable must not install this allocator.

Important interpretation: `allocations_prepared` consumes its baseline-owned input.
If the call frees that input, scratch/output allocations can be masked by the released
baseline space. `peak_live_delta_bytes` is the high-water total process LIVE above the
input-held baseline, NOT peak newly allocated scratch bytes; zero does not mean no
scratch allocation. `allocated_bytes` still records cumulative requests. The retained
saturating delta also hides negative net live change; a signed net metric can clarify
ownership transfer. RSS and allocator-resident bytes are separate, unmeasured quantities.
This caveat was sent to the root harness owner; no claim of allocator memory cost is
valid without specifying which gauge is being compared.

## Emerging suite source audit

Archive suite: `squish-backend/benches/{archive_latency,archive_allocations,workloads}.rs`.
It invokes shipping public writer/reader APIs, constructs fixtures outside samples,
uses equal-length ZIP names, holds 4 MiB content fixed for member-count sweep and
32 members fixed for byte sweep, and reports final ZIP bytes. Strict read and
canonical rebuild are labeled separate controls, not naively subtracted timings.
Fanout uses one unique 64 KiB blob with F owner bindings: expanded bytes/manifest
size increase intentionally while unique bytes remain constant.

The graph fixture has valid zero-operation/zero-region/zero-definition Module IR,
exact source digest/envelope, dense import declarations and explicit resolved edges.
Within each topology U=128 and source bytes/E stay fixed as G varies. Root ownership
and `_providers` path expansion change encoded ZIP bytes with G; reported archive
bytes/name overhead must be considered alongside the predicted G^2/G*E counters.
Hand-authored unused semantic-string payload is a legal IR ownership probe, but
not a claim about a frontend-realistic useful computation. Suggested oracle extension
sent to owner: compare relocated edge topology by logical-path mappings, not only
unit/source/assets equality and import counts. Repeated identical producer IR bytes
are checked for exact reproducibility; write(read(x)) is not assumed required for
all provider-grouping representations.

Core suite: `squish-link/benches/support/core_suite.rs` plus separate executables.
Real frontend fixtures feed verified persistence, linking and instantiation APIs.
The suite includes prepared-owned-input and clone-plus-call boundaries separately,
borrowed controls, exact text oracles, document/trace validation and recorded stage
counters. First/last identical-body macro probes hold definition count, expansion
count and output fixed while changing origin lookup row position. Distinct scalar
argument values are ignored by the macro, keeping output fixed and discriminating
linear repeated-value versus quadratic distinct-value interning.

Two calibration notes sent to compiler owner:

1. Use decoded container's `object_digest()` in UnitRevision, matching production,
   rather than separately applying ObjectDigest::of to encoded container bytes.
   This makes source/provenance identity faithful even if the linker does not itself
   cross-check that digest in this path.
2. Scalar literal/insert fraction fixtures hold operations/regions/output fixed,
   but source byte size differs and is recorded. Each selected scalar region is
   used once; this does not isolate K reuses of one static fact. A nested reusable
   macro with one RenderText call body is the discriminating reuse fixture.

No suite was compiled/executed locally. Type validity and oracles remain pending
hosted smoke; actual timing/allocation conclusions remain pending GHA measurements.

## Final authored-fixture corrections and calibration limits

Owner updates re-inspected:

- Core UnitRevision now uses `container.object_digest()`.
- Core adds `reused_scalar`: one nested macro RenderText region is evaluated K
  times; static/dynamic alternatives retain signatures/frame counts/arguments and
  exact emitted text. Scalar-region ownership selects the Module for this fixture,
  rather than incorrectly benchmarking unrelated Entry facts.
- Archive relocation oracle now compares sorted triples of exact importer source
  attachment bytes, import slot, and exact target attachment bytes. Fixture source
  attachments are unique, so this establishes graph topology, not merely counts.
- Common allocator support self-checks explicit alloc/zeroed/grow/shrink/dealloc
  accounting before sampling; latency executable still uses the ordinary allocator
  outside this tiny explicit wrapper self-check.

Collector `scripts/perf/mechanisms.py` checks modes and JSON counters, retains raw
samples, does not divide peak-live gauges by iterations, records binaries and build
wall time, and saves partial failure reports. Two interpretation limits were sent
root: Cargo bench profile inherits release unless bench overrides exist, so report
bench inheritance/overrides (`CARGO_PROFILE_BENCH_*`) as well as release settings;
and alternatives currently execute all samples sequentially rather than paired
AB/BA. Small first/last differences should be corroborated by reverse-order or
independent runs. Mechanism slopes/counts remain descriptive until actual hosted
data exists; none of these source checks establishes a measured improvement.

## Pre-GHA final static verdict

Final authored core/archive fixtures and shared support were re-inspected after
owner corrections. No concrete Rust compilation blocker or semantically invalid
fixture was identified by this source pass. This is not a compilation verdict.

The provenance-derived `origin_scan_comparison_floor` includes observed frame
call/definition origins and witnessed SourceSpan lookup row positions. Region
fallback and other substitutions can add uncounted lookups, so its lower-bound
label is appropriate; it must not be reported as an instrumented exact count.
Allocator self-check expectations (4 successful allocation/reallocation calls,
136 cumulative requested bytes, 2 deallocations, 2 reallocations, 80-byte incremental
peak, restored baseline live bytes) match the explicit allocation sequence.

No production code was changed and no local Cargo/npm was run. Commit and hosted
smoke/full mechanism run must supply compilation, semantic-oracle and actual
measurement evidence before the hypotheses above become empirical findings.
