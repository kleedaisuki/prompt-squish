Status: full core repair compiled and passed native/quality hosted checks at `0b1c732`;
its first same-host measurements exposed regressions described below. Follow-up repairs

The published v1.2.0 tag remains immutable. Historical baseline/index results remain in

## Contracts and concrete mechanisms

| Reviewed mechanism | Implemented representation / boundary | Preserved observable contract |
| --- | --- | --- |
| Scalar interning scans every previous string | Invocation-local bounded small-domain lookup promotes once to `HashMap<String, u32>` after eight arena entries. New values enter the vector once; large domains do not scan growing prefixes. | First-insertion IDs, entry duplicate first-match behavior and exact canonical trace IDs remain unchanged. The randomized map is never iterated or serialized. |
| Canonicalization clones all scalar text and binary-searches per reference | Sort original integer IDs by string value, move owned strings into the unique sorted pool, construct one dense old-ID remap. | Lexicographically sorted unique output, frame args and external-argument origin references are identical. No string payload clone is needed. |
| Immutable Call/Operation/Definition/fact copies per invocation | Machine tasks borrow `Argument`/`Fill` slices for the external program lifetime. Operations, linked definitions, StaticScalar text/segments and StaticMatch capture maps are borrowed. | Every literal segment, including empty ones, still emits its occurrence, provenance and semantic budget charge; scalar/fill ordering and errors are unchanged. Required owned output strings/occurrences are not falsely called avoidable copies. |
| Region selection temporary vectors and arena copies | One lazily allocated dense flag array, borrowed Call args and canonical borrowed region traversal. | Duplicate/unordered region references cannot reorder materialization or charge the 8 MiB cap twice; 1 MiB per-fact bound and empty contributions remain. |
| Duplicate internal unit/image validation | Raw public boundaries validate unchanged units once; a crate-private trusted middle entry consumes that validation. `ValidatedImage` has private fields and one verifying constructor, then assembly does not reverify. | Public raw APIs still reject malformed units, including structurally invalid unreachable snapshot units. Public cached-image reconstruction remains verified. |
| Snapshot/image structural checks miss cross-object relationships | Public reconstruction checks actual root/signature, definition coverage/IDs/symbol/signature/body ownership, exact symbol map and every actual Call relocation/signature against raw units. | Newly rejected inputs are forged/inconsistent images, not valid formerly working programs. Missing-origin/runtime budget diagnostics remain intact. Legacy raw reconstruction still accepts caller-supplied digest labels; the prepared path does not. |
| Whole-program clone duplicates all unit/fact/debug payloads | One private `Arc<ProgramData>` publishes immutable executable storage. `SharedUnitClosure` carries `Arc` raw units and snapshot evidence. | Public accessors and existing owned methods remain; clones retain the same image, unit and fact allocations. Independent entries never merge namespaces. |
| Shared modules repeatedly validate/hash/compile pools across include/target scopes | Sealed `ValidatedUnit` receipt + `PreparedUnit` session capability, with whole-unit `OnceLock<Result<PreparedFacts, LinkError>>`. | Exact immutable raw IR and actual revisions are bound once. Only first reachable specialization compiles the complete referenced pool; successes and source-qualified errors are retained for subsequent scopes. |
| Accumulated definition/relocation arrays sorted after every unit | Append in ascending canonical unit slots and validated dense local arena order. | The final address/operation order is already canonical; no per-prefix sorting or wire-order change. |

Large-domain expected hash-map lookup work is proportional to key hashing/equality, not the
old explicit quadratic prefix scans. This is not a worst-case proof against arbitrary hash
collisions. The fixed small-domain path checks at most eight existing values per lookup;
its work does not grow with a large invocation's value count. Once the arena exceeds eight
entries, promotion records each prefix value's **first** ID and indexed mode remains active.
The index owns one extra key per distinct string only after promotion; that memory tax must
be measured, not concealed. Canonicalization moves string payloads with integer order/remap
storage. The cutoff is a conservative bounded policy, not a universal optimal crossover.

## Verified preparation and independent linking

The safe IR-owned receipt exposes `ValidatedUnit::new(Arc<Unit>)`, `decode(bytes)`,
`unit()`, `revision()`, `debug_digest()` and `encode()`. Its identity fields are private.
Fresh verification derives the actual canonical identities from the immutable raw payload;
decoding carries actual identities from the checked container, including accepted optional
noncritical debug extensions. Encoding a receipt does not revalidate/rehash its unit merely
to recover metadata already proven by that receipt. Manager uses it instead of encoding then
decoding its own container, or decoding a cached unit and container separately.

`PreparedUnit::from_validated(receipt)` consumes this sealed proof without another validator
or arena hash. `PreparedUnit::new(raw_arc)` is a safe convenience wrapper, never an unchecked
constructor accepting asserted digest labels. It is intentionally **not eager middle work**:

```text
frontend or checked container decode
  -> sealed raw proof + actual revisions
  -> PreparedUnit (no regex engine / scalar materialization yet)
  -> first reachable link: whole-unit specialization -> retained facts + origin index
  -> each independent scope: metadata/closure checks -> symbol/signature binding -> image
  -> instantiate (immutable borrowed program/facts) -> backend
```

`link_prepared` verifies snapshot kind/source and exact semantic/object revision against every
provided capability, then specializes reachable units in canonical source order. Resolution,
module/entry include rules, cyclic imports, duplicate symbols and every call signature remain
per-scope checks. Snapshot metadata checks are not substituted by a process-global link map.
`reconstruct_prepared` validates the persisted image plus all exact cross-object relationships
and shares existing facts/object-local provenance indexes; cache hydration does not recompile
patterns already initialized in this invocation.

`PreparedUnit::stats()` returns `None` before successful initialization (and after failure).
It never triggers work. `specialize()` explicitly triggers first-reachable-equivalent whole-unit
work and returns counters, or the cached error. Counters describe retained fact/pool volume,
not newly performed work in every link. `OnceLock` retains no host-path-based global cache and
no cross-run regex-engine artifact. Multiple threads may share immutable capabilities; their
initialization is synchronized without introducing mutable IR or cyclic strong ownership.

### Crucial regex acceptance boundary

The previous linker structurally verified all supplied snapshot units, but ran the middle
end only on reachable units. Preserve that distinction:

- Within a **referenced** unit, an invalid pattern in an uncalled macro must still fail before
  execution; the entire unit pool is compiled on first specialization.
- A wholly unreferenced archived unit receives no new engine validation merely because its
  archive is loaded. Archive reader structural/source/import validation and manager pruning
  still occur before preparing the selected dependency units.
- Local frontend global strict validation is unchanged; its checks are not replaced by this
  lazy middle cache. Unreferenced local units acquire no additional middle fact work.

This is lazy whole-unit specialization at the existing reachability boundary, **not** lazy
per-pattern error suppression. A private receipt prevents a forged old object label from
selecting facts produced from a different unit. Source qualification includes the actual
object revision retained by the receipt, not only semantic identity.

## API/ownership details

Additive public paths:

- `SharedUnitClosure { snapshot: Arc<ResolutionSnapshot>, units: BTreeMap<SourceKey, Arc<Unit>> }`
  and `StaticLinker::link_shared` avoid copying raw IR but remain fully validating raw APIs.
- `PreparedUnitClosure { snapshot: Arc<ResolutionSnapshot>, units: BTreeMap<SourceKey, PreparedUnit> }`
  and `StaticLinker::link_prepared` reuse sealed validation, identities and initialized facts.
- `LinkedProgram::reconstruct_shared` is the safe raw cached-image boundary;
  `reconstruct_prepared(image, prepared_units)` is the safe receipt-backed boundary.

Owned wrappers remain available. The `OptimizedUnit.unit` field now holds `Arc<Unit>`;
consumers borrow with `as_ref()` or deliberately clone the underlying unit if independent
mutable ownership is actually required. This public field-type migration is explicit; do not
claim every source-level field assignment remains compatible. Persistent wire format, source
origin IDs and object-qualified traces are not changed by sharing.

## External grounding

The standard library's [Arc contract](https://doc.rust-lang.org/std/sync/struct.Arc.html)
supports shared ownership of one allocation with cheap reference-counted clones; atomic
reference counts are not free, so this design chooses one program allocation rather than
an Arc for every operation. [HashMap](https://doc.rust-lang.org/std/collections/struct.HashMap.html)
provides production-maintained keyed lookup with randomized hashing; the randomized layout
is session-only and never defines trace IDs or serialization order. [OnceLock](https://doc.rust-lang.org/std/sync/struct.OnceLock.html)
provides synchronized one-time initialization; caching `Result` is a project decision to
retain a source-safe failure rather than repeatedly compile the same rejected pool.

Peer-reviewed [RustBelt, POPL 2018](https://plv.mpi-sws.org/rustbelt/popl18/) motivates reasoning
about abstraction invariants and ownership boundaries. Our sealed receipt is an engineering
application of that discipline, **not a claim of formal verification of this compiler**.
[Build Systems a la Carte, ICFP 2018](https://www.microsoft.com/en-us/research/publication/build-systems-la-carte/)
separates reusable work from dependency/scheduling decisions; here unit specialization is
reusable while each entry's dependency closure and symbol binding remain independent.

### Mechanism and discriminating repair

The former unconditional `HashMap<String, u32>` removes unbounded equality scans, but hashes
an entire long value for every lookup and duplicates it as an owned map key even when the
value domain contains only one string. Entry setup also hashed the value again when recovering
its frame ID. The approximately 4/64 KiB peak increases agree with this duplicated-key cost.
This is a source-supported causal hypothesis, **not a measured attribution of every lost
nanosecond**; the next controlled run must test it.

`instantiate.rs::ScalarIndex` now scans a fixed prefix of at most eight arena entries and
promotes once beyond that size. Tiny repeated long values therefore need no hash map or extra
key copy. The high-cardinality path still uses the standard randomized hash map rather than
reintroducing an unbounded quadratic scan or adopting a non-adversarial custom hasher. Entry
setup derives first-match frame IDs during its existing sorted argument traversal. Initial
duplicate arena positions are retained; promotion uses `entry.or_insert` and never rewrites
first-insertion IDs. Canonical trace ordering, external-argument origins, per-occurrence
provenance, budgets and failure contexts are unchanged.

Focused regressions cover empty/Unicode values, a 64 KiB value reused 1,024 times without an
index, promotion with duplicate prefix entries, the eight/nine-entry transition, 2,048 distinct
values compared against the previous first-match oracle, and the real public instantiator
with twelve entry arguments (long/empty duplicates straddling promotion). Existing complete
output/budget oracles remain. Initial candidate-only public fixtures with 1/8/9/16 distinct
4 KiB arguments also change call count, source size and emitted text; they are **joint scaling**
controls, not isolated evidence of crossover cost. Follow-up fixed-16-call fixtures vary domain
cardinality 1/8/9/16 at the same per-argument width, source byte count and emitted text. Their
semantic pools and trace scalar arena necessarily differ. Existing same-K repeated/distinct
2,048-value controls retain the large-domain check. No local Cargo execution was performed; hosted validation is mandatory.

The design retains the standard hasher's adversarial protections. Rust's official
[HashMap documentation](https://doc.rust-lang.org/std/collections/struct.HashMap.html)
explicitly identifies long strings as a key-size regime where default hashing can cost more;
its algorithm is an implementation detail, not a portable performance contract. This repair
changes when indexing is useful, not correctness or externally visible IDs. The next run must
report the three negative fixtures, crossover controls and high-cardinality cases separately,
including both latency and allocation/peak taxes. Until then the original negative measurements
remain the evidence, not a claim that this source change has already erased them.

## Private shared scalar facts: execution versus public compatibility

The sixteen-region fixture exposes another real duplication: all sixteen regions reference
one canonical 64 KiB literal pool value, but execution previously retained sixteen separate
64 KiB `StaticScalar.text` strings. The repair introduces crate-private `ExecutableUnit` and
`SharedStaticScalar { text: Arc<String>, segments }`. Every actual raw/shared/prepared linker
and cached reconstruction now publishes this execution representation. It does **not** retain
a second public owned-fact map beside it, and does not serialize Arc handles into SOPack/IR.

Public `OptimizedUnit`, `StaticScalar { text: String }`, and both `MiddleEnd` methods retain
all their field/signature/value contracts. Their compatibility outputs materialize owned
Strings directly; they do not first build shared text only to clone it back into public
fields. Common private `MiddleFacts<S>` reuses the regex, selected-region and statistics policy
with two bounded text-storage builders. The private compatibility conversion is a move-only
adapter used by counterfactual tests, not the production route. Public owned-middle timing
controls therefore remain honest controls, not silently relabeled private preparation.

The internal builder interns **canonical literal StringId sequences**, not giant payload
hashes or display/source-name keys. Interning is local to one immutable unit specialization;
it is discarded after the facts retain their strong text handles. Regions with the same byte
concatenation but different ID sequences need not share storage. Each fact independently owns
its ordered original OpId/range segments, including empty contributions. Runtime occurrences
still resolve their own object-qualified origins and charge their own semantic work.

The 1 MiB single-fact and 8 MiB per-unit limits remain **logical per-region** limits. Sharing
one allocation cannot specialize extra regions beyond the previous cap; existing stats and
trace geometry remain identical. The raw sealed unit/revisions, lazy first-reachable whole-unit
regex validation, independent symbol scopes, correspondence verifier and cached error contracts
are unchanged. Allocation/peak measurements, not `OptimizationStats.scalar_bytes`, describe
physical storage after sharing.

Regressions require exact retained Arc identity for two 64 KiB region texts, distinct original
operations despite sharing, parity with public facts/statistics/raw IR, preservation of the
owned text buffer during compatibility conversion, aggregate-cap exhaustion despite repeated
identical text, empty facts after exhaustion, and Unicode/empty contribution ranges. The actual
complete document/trace/directive fingerprint comparison remains mandatory in hosted tests.
No latency recovery is claimed until the next exact-source same-host run; the candidate still
adds small reference-count/key metadata and its tax must remain visible in allocation rows.


### Identical-document verifier cache-context control

The `LinkedDocumentIr::validate` implementation is unchanged between `1bbf6cd` and `2cb7421`
(the only `validate.rs` source diff exposes an unrelated source-key helper). Same-K repeated
and distinct 2,048-value fixtures produce identical canonical document bytes, yet borrowed
validator medians increase from approximately 5.85 to 8.36 us in all three process passes.
That is retained as a measured negative; identical source/content does not establish identical
compiled code layout, heap placement or prior-stage cache/allocator context.

A narrow candidate-only `validate_document_fresh_owned` control runs only the existing
`scalar-values-e2048-*` fixtures. It clones the exact document **outside** timing/allocation
gauges, checks semantic equality outside samples, validates that fresh owned document using
the actual unchanged public method, then returns it so destruction is also outside timing.
The original borrowed `validate_document` row is untouched. This distinguishes some allocation/
cache-context effects but is not an end-to-end improvement, a comparative baseline row, or
permission to treat input cloning as free. Codegen/layout and carryover remain hypotheses;
no public validation or rejection contract is weakened to obtain a better benchmark.
