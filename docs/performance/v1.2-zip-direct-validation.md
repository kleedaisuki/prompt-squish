# Direct canonical ZIP validation and borrowed transport

Date: 2026-10-02. Status: implemented; hosted validation and measurements pending.

## Reused evidence and boundary

The original mechanism report (`v1.2-archive-mechanisms.md`) measured owned ZIP
reading with allocation requests proportional to twice the payload: each member
was copied, then the complete archive was regenerated for strict equality.
CRC likewise traversed each body twice. This change removes redundant work, not
canonicality, integrity, platform portability, or existing owned API behavior.

## Representation and contracts

`ArchiveEntryRef<'a>` contains only borrowed path and body slices. The borrowed
reader retains no independently owned payload and its return lifetime is tied to
the input. Existing `ArchiveEntry` APIs remain owned compatibility wrappers.

The writer validates names and resource bounds, sorts borrowed descriptors,
reserves the final ZIP once, emits local bodies, and retains only `(offset, CRC)`
per member. It writes the central directory directly into the reserved output;
there is no central-directory staging buffer or second body CRC calculation.

The reader walks local records contiguously, validates body CRC once, and stores
borrowed slices plus offsets/CRC. It then walks the central records in precisely
the same order and checks every field and name against the local record and the
fixed writer contract. EOCD must immediately follow the final central record and
immediately precede EOF. This excludes hidden members, unused prefixes, orphaned
central entries, duplicate directories, comments, descriptors and trailing data.

| Record | Required validation |
| --- | --- |
| Local | Signature, version 20, UTF-8-only flags, STORED method, DOS time 0/date 33, CRC, equal stored/content size, bounded UTF-8 portable path, no extra field, strictly ascending raw path order. |
| Central | Signature, Unix creator/version 0x314, extraction version 20, same flags/method/date/time, exact local CRC/size/name, zero extra/comment/disk/internal attributes, mode 0100644, exact local header offset. |
| EOCD | Signature, disk fields zero, both counts equal parsed members, exact central size and start, comment length zero, no trailing byte. |
| Global | Archive/content/member/classic-ZIP bounds, case-folded uniqueness and file/directory prefix collision rejection. |

Offset arithmetic is bounded by successful fixed-header/name/body slices; the
shared slice helper uses checked addition. Bodies are not copied or allocated
before complete archive acceptance. Names still incur validation/lowercase-set
metadata allocations; no claim of zero allocation is made.

Necessary complexity is O(D + L + N log N) for payload CRC, name validation and
sorting/set checks. Borrowed read allocation is O(N + L), independent of D at
fixed member count/path lengths. Owned read adds exactly the required ownership
copy of D, but no regenerated B-byte archive. These are source-derived models;
actual hosted counters must establish the observed constants.

## Regression evidence required

The frozen pre-repair codec in `zip_legacy_oracle.rs` is test-only and intentionally
keeps the original reconstruction strategy. Tests compare exact writer bytes and
reader acceptance with it, mutate every bit of every byte of a small binary/UTF-8
archive, truncate at every position, reject trailing bytes, and exercise portable
name collisions, all three resource limits and the canonical empty archive.
A coherent payload mutation with both CRC fields updated remains accepted by both
readers, distinguishing strict validation from unconditional mutation rejection.
The borrowed round-trip additionally verifies that body pointers alias input.

No local Cargo build/test was run, as requested for disk constraints. rustfmt was
run; production/fixture compile and test evidence must come from GitHub Actions.

## Primary references and judgment

[PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)
defines local, central and end records (sections 4.3.7, 4.3.12 and 4.3.16).
This implementation deliberately accepts only the existing canonical subset, not
all ZIP extensions permitted by that specification.
[Reproducible Builds archive guidance](https://reproducible-builds.org/docs/archives/)
identifies ordering and archive metadata as reproducibility inputs. Canonical
fixed metadata remains unchanged; a faster permissive reader is not a valid
comparison or replacement. The representation follows established zero-copy
binary parsing practice while ownership wrappers retain external contracts.
