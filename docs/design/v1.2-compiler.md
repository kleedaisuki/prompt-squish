# v1.2 Compiler and Portable Packaging Contract

## Frontend and relocatable unit IR

The existing flat operation/region arena remains authoritative. The source roots are
`xs:entry`, `xs:module`, `xs:pack`, and `xs:sopack`. Pack reuses `EntryObject`;
Sopack uses `SopackObject { module: ModuleObject, root_region: RegionId }`, so public
macro declarations and asset collection retain a single defining-unit identity.
A Sopack root can import modules, declare macros, collect assets, and invoke macros.
It cannot contain include directives, including inside uncalled macro definitions.

`Op::Asset { path: StringId, name: StringId }` is a portable reference to complete
file bytes. The frontend never reads asset files. The manager freezes bytes and
resolves the path relative to the operation's defining unit, not the macro caller.
A macro moved into a Sopack must keep this identity through expansion and source
relocation. Archive member names reject traversal, empty components, absolute paths,
control characters, backslashes, and platform drive prefixes.

`Op::Include { import: ImportId, path: StringId, name: StringId }` uses an explicit
import edge with `expected_kind = Entry`; normal imports require Module. The resolver
must reject an included Module, Pack, or Sopack. Names default to `basename.prompt`;
asset member names default to the relative input path. Relative source paths may
contain parent components (for sibling project resources), but archive names may not.

Pack/Sopack wire variants are 3/4; Asset/Include operation tags are 9/10. Unit container
kinds Pack/Sopack are 8/9. Typed validation, canonical codecs, and JSON inspection all
recognize these kinds. Source relocation uses common mutable header/source/archive
accessors rather than teaching every storage layer a separate variant layout.

The frontend advertises `xmlsquish.dsl/0.4`, `xmlsquish.xml/2`, and producer
`xml-2`, deliberately invalidating old semantic caches. Regex ABI is unchanged.

Focused frontend fixtures exercise both roots, portable container round trips,
entry-only include edges, default names, macro-owned assets, and traversal rejection.
The frontend/IR crates were checked locally with `cargo check -p squish-xml-front
-p squish-ir --offline -j 2` (3.75 seconds). Initial focused tests passed: frontend 16/16 (0.03 seconds execution), IR 49/49
(0.01 seconds execution). Further cross-validation cases cover container-kind/root
mismatches, include import-kind tampering, and linked-image Pack/Sopack kinds.
Full workspace/integration testing belongs
in CI; packaging/linker/manager behavior is outside the frontend ownership boundary.

## Linker, execution and cache boundaries

The linker consumes portable units irrespective of local/SOPack origin. Module imports may
bind Module or Sopack providers; Sopack root macro declarations are therefore reusable.
Include bindings must target Entry and do not join the parent symbol closure: each child
entry is linked and emitted independently, preventing unrelated child macros from colliding.

`InstantiateOutput.directives` carries ordered `ArchiveDirective::Asset/Include` requests.
Each request records defining `SourceKey`, literal path/name and complete `TraceRef`; Include
also records `ImportId`. The manager resolves that ID in its frozen snapshot, rather than
re-reading paths during evaluation. All syntactic asset references must be frozen before
planning and included in action input identities, even when dynamic expansion later selects
only a subset. Persistent directive codecs preserve selection and provenance across runs.

The source-preserving middle end computes unbound facts before symbol binding. The linker
retains those facts and builds dense definition-address indexes, and the evaluator consumes
constant matches/scalar bodies while reconstructing exact frames, origins and budget costs.
Portable archives persist semantic IR, never device-specific regex engine memory.

Release frontend builds retain structural validation but skip the redundant codec roundtrip;
debug builds and dedicated codec tests retain it. Local verification ceased once the user
reported disk constraints; all further integrated validation belongs to GitHub Actions.
