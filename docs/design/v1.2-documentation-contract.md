# v1.2 documentation and product surfaces

Date: 2026-10-01. Scope: README, normative DSL manual, localized site,
release metadata, and the executable-bundled Agent Skill.

## User-facing model

Distinguish four source-unit roots (`module`, `entry`, `pack`, `sopack`) and
three distributable products (`.prompt`, `.pack`, `.sopack`). A pack is a final
deliverable; a SOPack is an immutable relocatable library, not a final pack or
a copy of private cache state. Import addresses module definitions; include
addresses entries. Assets retain bytes and defining-source ownership even when
their macro is invoked from a different project.

The pipeline presentation must expose front end, optimization, linking and
backend. Keep existing namespace and chapter URLs, add directive anchors to
the existing reference, and retain every historical release. Color highlights
product roles, but role names, file extensions, and descriptions must work
without color or JavaScript. Telemetry is opt-in project metadata, not a
required part of a reproducible product.

## Release boundary

v1.2 intentionally invalidates old derived cache schemas. User source and
manifest migration should be explained separately from cache invalidation.
Never claim cross-device reuse of private caches: portability belongs to the
SOPack contract. Release assets remain the six native archives, SHA256SUMS,
and SKILL.md; pack/sopack are products built by those binaries.

## Validation

Use lightweight metadata/translation consistency checks locally. Delegate
Astro checks, the site build, browser validation, and workspace tests to CI.
Finalize syntax examples against the compiler and manager implementation,
not against aspirational requirements.

### Implemented public examples and lightweight checks

- Compiler coordination confirmed `asset path="..." [name="..."]` and
  `include path="..." [name="..."]`; import retains `src`, not `path`.
  Asset default names retain their relative path; include defaults to
  source stem plus `.prompt`.
- Manager coordination confirmed target backends `squish`/`prompt`, `pack`,
  `sopack`, their matching suffixes, and dependency
  `{ sopack = "vendor/common.sopack" }` with ordinary `add --path` / `remove`.
  Examples explicitly select the backend rather than relying on inference.
- Telemetry coordination confirmed global `--trace=off|summary|events`, bare
  `--trace` as events, the `XMLSQUISH_TRACE` fallback, and persisted
  `<target-dir>/metadata/traces/<invocation>.jsonl` records with schema
  `xmlsquish.trace.v1`. Explicit off overrides environment configuration;
  trace I/O failure is warning-only (`TRACE001`), not a build failure.
- A Python metadata check on 2026-10-01 verified root manifest/lock agreement
  at 1.2.0, matching release JSON, six native archives, 38 distinct sitemap
  routes, and the bundled skill's `prompt-squish` identity. No Cargo/npm
  build, install or test was performed locally: available disk space is a
  user-declared constraint. Browser assertions were updated, not executed;
  visual rendering and TypeScript checking still require CI evidence.
