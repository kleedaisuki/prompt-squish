# v1.2 reproducible ZIP and portable SOPack

## Transport contract

`crates/squish-backend/src/archive.rs` provides pure byte APIs with no filesystem or host state:

- `write_reproducible_zip(&[ArchiveEntry], ArchiveLimits)` and `read_reproducible_zip(&[u8], ArchiveLimits)`.
- `write_sopack(&SopackPayload, ArchiveLimits)` and `read_sopack(&[u8], ArchiveLimits)`.
- `logical_source_path(&SourceKey)` returns a validated portable relative path.
- `content_digest(&[u8])` returns the BLAKE3 exact archive identity. This transport digest is distinct from IR's domain-separated SHA256 identities and repository lockfile SHA256.

Classic ZIP uses stored content, UTF-8 flag, UTF-8 bytewise name ordering, fixed 1980-01-01 00:00:00 DOS timestamp, Unix regular-file mode 0644, and no extra fields, comments, directory records, data descriptors, compression, encryption, or ZIP64. Default bounds are 256 MiB archive/content and 16,384 files. Input ordering and producer device do not affect output. Stored ZIP deliberately trades compression ratio for predictable startup/constants and byte stability independent of compressor upgrades.

Readers are intentionally restricted to canonical producer ZIPs, not arbitrary third-party ZIP files. Local records are bounds/CRC checked before allocation; regenerating canonical ZIP verifies the central directory and all header metadata, rejects hidden/trailing data, and avoids trusting central offsets. This costs another bounded archive-sized allocation; benchmark before replacing it with a more complex parser. Portable paths reject traversal, empty components, Windows aliases, forbidden characters, case-insensitive duplicates and file/directory collisions.

## Library schema and relocation

`SopackPayload` contains package name/version, stable metadata, typed compiled units, exact source bytes, exact asset bytes, a resolved import binding table, and public export names. Optional `metadata["manifest"]` is canonical package-manifest TOML supplied by the manager; producer must omit artifact targets, external dependencies, physical paths, and volatile data there. The archive contains `sopack.json`, `sources/<logical path>`, `units/<logical path>.xsir`, and content-addressed `assets/<BLAKE3>`; no finished prompt/pack products or undeclared members are accepted.

Source keys, attachments and every source record are rewritten before unit encoding. Original project-root source paths stay unchanged. The manager supplies `root_source` explicitly; package display names do not decide root ownership. Its logical spelling is retained as manifest `root_path`. Foreign providers are grouped internally by exact resolver package identity, then namespaced as `_providers/<content fingerprint>/<provider path>` to prevent same-name/version `src/lib.xml` collisions. Fingerprints include source kind, package name/revision, sorted logical paths and exact source bytes, assets by owner/path and bytes, compiled IR with normalized source/import/producer identities, and frozen binding graphs. Host checkout fields are excluded. G deterministic graph-color rounds (G provider groups) propagate content across every simple dependency path without recursive cycle handling. This conservative O(G * (G + E)) graph stage is expected to be small for normal package sets; many-provider tail workloads should profile it before adopting SCC/DAG-specific machinery. Identical provider content with duplicate logical paths is explicitly rejected rather than silently merging identity. Physical checkout paths and producer fingerprints are excluded from portable identities. Producer fields become fixed `xmlsquish/1.2.0` and `sopack-v1`; resolved import spellings become archive-local `sopack:<logical target path>`. Exact XML source content is not rewritten, preserving diagnostics even if source text contains original import spellings.

On write, normalized `SourceKey::Project` uses source kind 5, `canonical_source=sopack:internal`, and exact revision `internal`. On read, all identities move to `canonical_source=sopack:<archive BLAKE3>` with exact revision equal to that digest and original package name. The digest is applied only on read, avoiding a circular archive identity. Import bindings and asset owners undergo the same relocation. Consequently an imported macro's asset lookup remains anchored in its defining archive module, never in the caller's directory.

SOPack roots retain their typed root region and module-compatible interface on write/read, preserving declared macros, interfaces, import edges, arena ownership, sources and assets. Module imports may bind a SOPack root to use its declared macros without producing an artifact. Converting a root to a plain Module would incorrectly orphan its packaging arena; therefore the typed root is preserved. Entry and Pack objects remain forbidden library contents. Declared import slots must have exactly one binding to a bundled module. All Asset operations must have defining-source/path byte bindings. Source records must match packaged SourceDigest/blob digest/byte length. Manifest JSON is limited to 8 MiB before decoding. Shared asset blobs are deduplicated on disk, but expanded materialized asset bytes and binding counts are separately bounded on read to reject fan-out allocation attacks.

## Evidence and testing

Focused backend tests cover binary/Unicode round trips, input-order determinism, fixed timestamps, empty ZIP, traversal/platform aliases, duplicate and prefix collisions, checksum/header/directory corruption, every truncation, bounds, metadata-only libraries, undeclared finished artifacts, relocation across different checkout paths, exact source identity mismatch, root preservation and provider path collisions. Local execution intentionally limited to `rustfmt`; Cargo tests/checks run through the root's remote GitHub Actions due to user disk/resource constraints.

## References

- [PKWARE ZIP APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT): stored files, CRC32 and ZIP record structure.
- [Reproducible Builds: archive metadata](https://reproducible-builds.org/docs/archives/): normalize archive metadata, ordering, timestamps and permissions.

The bounded stored transport is a mature engineering choice, not a new compression research contribution. Future optimization should measure canonical verification memory/CPU and asset fan-out first; introducing zero-copy shared blobs would require an explicit payload ownership/API change rather than silently weakening memory bounds.
