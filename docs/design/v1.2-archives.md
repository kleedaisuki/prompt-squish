# v1.2 reproducible ZIP and portable SOPack

## Transport contract

`crates/squish-backend/src/archive.rs` provides pure byte APIs with no filesystem or host state:

- `write_reproducible_zip(&[ArchiveEntry], ArchiveLimits)` and `read_reproducible_zip(&[u8], ArchiveLimits)`.
- Compatibility: `write_sopack(&SopackPayload, ArchiveLimits)` and `read_sopack(&[u8], ArchiveLimits)`.
- Production: `write_sopack_ref(&SopackPayloadRef, ArchiveLimits)`, `write_sopack_shared(&SharedSopackPayload, ArchiveLimits)`, and `read_sopack_shared(&[u8], ArchiveLimits)`.
- Borrowed ZIP: `ArchiveEntryRef`, `write_reproducible_zip_ref`, and `read_reproducible_zip_ref`.
- `logical_source_path(&SourceKey)` returns a validated portable relative path.
- `content_digest(&[u8])` returns the BLAKE3 exact archive identity. This transport digest is distinct from IR's domain-separated SHA256 identities and repository lockfile SHA256.

Classic ZIP uses stored content, UTF-8 flag, UTF-8 bytewise name ordering, fixed 1980-01-01 00:00:00 DOS timestamp, Unix regular-file mode 0644, and no extra fields, comments, directory records, data descriptors, compression, encryption, or ZIP64. Default bounds are 256 MiB archive/content and 16,384 files. Input ordering and producer device do not affect output. Stored ZIP deliberately trades compression ratio for predictable startup/constants and byte stability independent of compressor upgrades.

Readers are intentionally restricted to canonical producer ZIPs, not arbitrary third-party ZIP files. Borrowed local records are bounds/CRC checked and directly matched against canonical central records and end-of-directory metadata. Names, offsets, counts, timestamp/flags/mode constants and exact EOF are verified without allocating file bodies or regenerating a second archive. The original regeneration validator remains test-only as a differential oracle. Portable paths reject traversal, empty components, Windows aliases, forbidden characters, case-insensitive duplicates and file/directory collisions.

## Library schema and relocation

`SopackPayload` contains package name/version, stable metadata, typed compiled units, exact source bytes, exact asset bytes, a resolved import binding table, and public export names. Optional `metadata["manifest"]` is canonical package-manifest TOML supplied by the manager; producer must omit artifact targets, external dependencies, physical paths, and volatile data there. The archive contains `sopack.json`, `sources/<logical path>`, `units/<logical path>.xsir`, and content-addressed `assets/<BLAKE3>`; no finished prompt/pack products or undeclared members are accepted.

Source keys, attachments and every source record are rewritten before unit encoding. Original project-root source paths stay unchanged. The manager supplies `root_source` explicitly; package display names do not decide root ownership. Its logical spelling is retained as manifest `root_path`. Foreign providers are grouped internally by exact resolver package identity, then namespaced as `_providers/<content fingerprint>/<provider path>` to prevent same-name/version `src/lib.xml` collisions. Fingerprints include source kind, package name/revision, sorted logical paths and exact source bytes, assets by owner/path and bytes, compiled IR with normalized source/import/producer identities, and frozen binding graphs. Host checkout fields are excluded. Iterative SCC condensation produces dependency-first Merkle fingerprints; full labelled cyclic topology is encoded using deterministic member ordinals. Unique-seed components need no refinement rounds. Tied cyclic seeds first use a canonical sorted-edge traversal from the lexicographically smallest uniquely occurring seed (including the distinguished root). This visits each SCC member and edge once; only genuinely unanchored ties use bounded partition refinement, and unresolved symmetric foreign providers are explicitly rejected. The actual root role is a host-independent seed anchor, preserving acceptance of equal-content cycles involving the packaging root. Identical provider content with duplicate logical paths is explicitly rejected rather than silently merging identity. Physical checkout paths and producer fingerprints are excluded from portable identities. Producer fields become fixed `xmlsquish/1.2.0` and `sopack-v1`; resolved import spellings become archive-local `sopack:<logical target path>`. Exact XML source content is not rewritten, preserving diagnostics even if source text contains original import spellings.

On write, normalized `SourceKey::Project` uses source kind 5, `canonical_source=sopack:internal`, and exact revision `internal`. On read, all identities move to `canonical_source=sopack:<archive BLAKE3>` with exact revision equal to that digest and original package name. The digest is applied only on read, avoiding a circular archive identity. Import bindings and asset owners undergo the same relocation. Consequently an imported macro's asset lookup remains anchored in its defining archive module, never in the caller's directory.

SOPack roots retain their typed root region and module-compatible interface on write/read, preserving declared macros, interfaces, import edges, arena ownership, sources and assets. Module imports may bind a SOPack root to use its declared macros without producing an artifact. Converting a root to a plain Module would incorrectly orphan its packaging arena; therefore the typed root is preserved. Entry and Pack objects remain forbidden library contents. Declared import slots must have exactly one binding to a bundled module. All Asset operations must have defining-source/path byte bindings. Source records must match packaged SourceDigest/blob digest/byte length. Manifest JSON is limited to 8 MiB before decoding. Shared asset blobs are deduplicated on disk and in immutable Arc-backed read storage. Expanded logical asset bytes and binding counts remain separately bounded on read, so sharing does not weaken acceptance limits.

## Active repair design: SCC identities and shared archive views

The original provider graph executed G rounds over all G providers and repeatedly sorted edges. Replace that policy with an iterative strongly-connected-component (SCC) decomposition, a condensation DAG processed dependency-first, and Merkle-style component/member identities. The graph storage has one sorted edge list per node. A singleton component gets a normal Merkle fingerprint. For a cyclic component whose source/IR/asset seeds are unique, sort members by seed and encode the full labelled topology once, using stable member ordinals for internal edges and finished target fingerprints for external edges. This preserves topology, including cycle length, unlike bounded neighborhood hashing.

The actual root role is included in content seed identity, distinguishing the root from equal-content foreign providers. For tied seeds, a uniquely occurring seed canonically anchors sorted-edge BFS; strong connectivity reaches every member without per-round scans. One reusable visit-mark array avoids per-component whole-graph initialization. Only unanchored seed ties inside one SCC need partition refinement: initialize from base seed and external targets, refine using labelled internal target partitions until every member is unique or the partition stops splitting. Unresolved ties are explicitly rejected as ambiguous content-equivalent providers; host paths must never break a tie. This is a deliberate acceptance constraint rather than claiming general graph-isomorphism canonicalization. Unique-seed 512-node cycles and isolated nodes execute no refinement rounds and no G-squared whole-graph work. The algorithm uses a new provider identity domain (`sopack-provider-scc-v3`); readers accept existing schema-1 archives unchanged. Loaded identity/path spelling is preserved when rewriting an already relocated single archive group, including older `_providers` paths.

The SCC method follows established linear graph decomposition [Tarjan, SIAM Journal on Computing 1972](https://epubs.siam.org/doi/10.1137/0201010). The condensation's content references adopt proven content-addressed object practice exemplified by [Git object storage](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects). The cyclic tie boundary is a graph-canonicalization issue, not an excuse to implement an unbounded isomorphism solver in a packaging hot path; future broader acceptance needs discriminating cyclic fixtures and explicit resource guarantees.

Archive ownership changes are internal and additive: `SharedSopackPayload` stores compiled units and exact sources/assets behind `Arc`; assets sharing one digest share one immutable allocation. `SopackPayloadRef` exposes borrowed byte/unit maps for staging-free writer calls. Existing owned APIs remain compatibility wrappers. ZIP workers own the canonical borrowed ZIP view/parser separately; SOPack uses those views and avoids copying source/asset contents into staging entries. Expanded logical-byte limits remain enforced even when physical storage is shared. The IR owner provides borrowed normalized codec projections to eliminate seed/output tree clones while preserving exact wire semantics. No local Cargo compilation or benchmarks are permitted; hosted CI must measure scaling and allocation probes.

### Final repair implementation and evidence contract

`archive/provider_graph.rs` performs iterative Kosaraju decomposition (the same linear SCC abstraction as the referenced Tarjan result, using a two-pass implementation to avoid recursion), one-time edge ordering, dependency-first component hashing, and tie-only canonical partition refinement. Source and asset BLAKE3 digests are cached by live borrowed slice identity within one write call; pointer values are cache keys only and never enter serialized bytes or fingerprints. A single-provider write returns existing logical paths directly, preserving old schema-1 `_providers` names without recomputing them.

A safe `VerifiedUnitEncoding` handle validates each immutable source unit once, then streams its borrowed normalized semantic IR seed and encodes the final relocated unit once into its output container. Each projection still validates substitution metadata; no unchecked public bypass is introduced. The additive `semantic_unit_digest_with` / `encode_unit_container_with` public wrappers preserve their trust-boundary checks. Neither path clones semantic-string tables, operation arenas, source line maps, or whole units. Source/asset ZIP entries borrow input storage, and shared reads allocate each unique asset digest once. New tests explicitly demonstrate shared pointer identity and a limit where ZIP transport succeeds but expanded SOPack alias bytes are rejected.

Archive benchmarks retain named owned compatibility controls while adding primary borrowed ZIP/shared SOPack mechanisms. Untimed oracle rows use schema `xmlsquish.archive.oracle.v1`: ZIP checksums compare exact archive/member bytes, SOPack checksum compares full typed IR normalized to source-content identities plus exact source/assets, imports, exports and root. Provider namespace fingerprint changes are deliberately excluded from cross-version semantic oracles. For historical fixtures with distinct source content, content-addressed normalization remains byte-identical. Equal-content fixtures use explicit-root BFS with unique sorted import slots to assign canonical source ordinals, retaining every node and import endpoint. The oracle rejects colliding identities when the root cannot reach every unit/source rather than projecting away ambiguity. Uniform-ring checks compare producer/readback semantics, physical identity permutation, and a same-size root-reachable graph whose final edge closes a non-root cycle; that topology change must alter the semantic checksum. `scripts/perf/baseline_archive_oracle.patch` is a baseline-compatible benchmark-only patch, not a production source overlay. Local work was limited to file editing, rustfmt and baseline patch construction; actual compilation, correctness execution and allocation/latency measurements are hosted-only.

### Follow-up: measured read peak versus avoidable lifetime overlap

The preliminary same-host 0b measurement reported 512-provider cycle shared-read cumulative allocation falling from 13,711,988 to 6,362,672 bytes, but peak live allocation rising from 3,508,139 to 3,965,467 bytes. Source inspection found avoidable scratch overlap, not a necessary consequence of immutable shared authority: the final `payload.as_ref()` validation adapter cloned all SourceKey map indexes plus import/export metadata while the decoded manifest and relocation table were still live.

The follow-up validates borrowed and Arc-backed maps through one generic contract without allocating a temporary payload view. It consumes manifest source/unit/import rows as they are transferred, moves package metadata into the returned payload, drops the relocation table after the final unit has acquired its own relocated keys, and drops the shared-asset cache/remaining manifest scratch before final validation. The returned payload retains all required source, unit, asset and binding ownership, and exact closure/source/asset checks remain unchanged. A focused test compares direct shared-map validation against the borrowed compatibility adapter for both valid and missing-source payloads. Reduction in actual peak awaits the next hosted measurement; the source argument is not reported as measured improvement.

The same preliminary 16 MiB / 32-member borrowed ZIP writer latency ratio was 1.038, so no writer acceleration is claimed. Its final Vec is the required product; additional storage consists of sorted borrowed member records, offsets/CRCs and portable-name validation metadata, not another payload-sized staging allocation. Inspection did not establish a simple payload-copy cause for that small negative latency result. ZIP read and provider graph gains must not be generalized into an unsupported universal write-speed claim.

### Source attachment fan-in hashing

Final shared/borrowed payload validation now maintains a bounded invocation-local lazy map keyed by each exact authoritative `SourceKey`. A cache miss computes domain-separated IR SourceDigest SHA256 from the immutable bytes found in the payload source map. Record-provided digest labels never populate the cache. Every occurrence still compares its expected SourceDigest, BlobRef digest and byte length against the cached actual digest and exact bytes. Manifest BLAKE3 verification remains a separate required transport/content check.

The fan-in regression builds 16 independently owned units with 32 source records, including the same 64 KiB diagnostic source in every unit. The validator's private successful hash-count result must report 17 computations (16 defining-source keys plus one shared diagnostic key), not 32 record hashes. A second regression forges the digest/blob labels consistently, corrupts blob labels or lengths in every unit position (including after cache population), and mutates actual shared bytes; all must reject. This memo is bounded by the supplied source map and drops at the end of one immutable validation call; it does not become a persistent identity authority. Hosted execution and any latency effect remain pending.
