# Invocation-scoped verified runtime snapshots

This design complements the mechanism-level naivety review. Runtime adapters are
additive: existing custom runtimes still implement owned `read_blob`, `write_blob`,
`lookup_action`, `link`, and `render` contracts. New default methods bridge those
interfaces and verify returned bytes against the requested digest and declared size.
Wrong legacy write identities remain corruption, never successful cache entries.

Production adapters acquire one lazily initialized `CasSession` shared by the action
index, manager consumers, and both publication spaces. The session cache is bounded
(default 8 MiB / 256 entries); callers explicitly hold `VerifiedBlob` snapshots and
`VerifiedAction` output handles. Eviction changes retention only, not the validity of
an already acquired immutable snapshot. Raw legacy CAS reads remain fresh, preserving
existing corruption-detection and filesystem mutability expectations across reads.

`read_verified` and `write_verified_blob` avoid unnecessary repeat hashing; the blob
constructor hashes exactly once and seals its identity with shared immutable bytes.
`lookup_action_verified` returns output buffers in declaration order. Publication's
`BlobStore::copy_to` uses the same session snapshot, rather than verifying a file and
then seeking/rereading it to copy. `publish_generation_verified` additionally passes
caller-held handles into a temporary publication view, covering outputs larger than
the cache budget without retaining them in a long-lived cache. This does not weaken any durable CAS publication,
SQLite critical action transaction, or filesystem synchronization barrier.

Cache-hit recency writes are advisory. `flush_advisory` allows invocation owners to
report an explicit finish failure. Production runtime drop provides best-effort
flushing without opening an index that was never used, and without poisoning durable
action success semantics. The index's explicit flush implementation remains owned
by the storage component.

Borrowed backend requests and shared linker closures likewise retain immutable data
through the real production implementation. Legacy plugins preserve the owned bridge.
The production backend copies only its required output trace, not the whole input
linked document; production linking retains shared unit handles.

Focused default-bridge unit tests in manager `runtime.rs` cover identity preservation,
wrong read/write digest rejection, ordered action output buffers, size mismatch, and
missing outputs. Compilation and execution must be performed in GitHub Actions;
no local Cargo/npm command is part of this change's verification.

The host snapshot test uses a zero-retention session and then corrupts the CAS path.
A fresh CAS read rejects the corruption; the explicitly supplied immutable snapshot
still publishes its original verified bytes with zero acquisition reads. This tests
both the eviction edge and the separation between snapshot identity and mutable paths.

## Prepared-unit linking and manifest identity

`BuildRuntime::link_prepared` accepts sealed `PreparedUnitClosure` handles. Its legacy
fallback converts them to shared raw unit handles and invokes `link_shared`; the
production adapter calls `StaticLinker::link_prepared` directly, retaining validated
units and their context-independent optimized facts across target/include consumers.
The shared raw fallback is compatibility-only, not the production optimization path.

The default verified-action adapter rejects a manifest whose key differs from the
requested action, before acquiring output bytes. Its constructed handle count is
exactly the declared output count; manager hydration must additionally validate this
count and each handle when injected runtimes override the method directly. A focused
wrong-manifest-key unit test covers this default boundary.

## Structured evaluator diagnostics

Runtime errors must preserve evaluator provenance rather than flattening errors with
`Display`. `BuildRuntimeError` retains an optional protocol diagnostic; existing
constructors and stable runtime codes remain unchanged. The manager consumes this
explicit authority into its existing MGB action diagnostics, retaining primary and
related locations. The compiler owns exact object-qualified origin resolution and
failure expansion frames; hosts must not infer a source from a basename or frame ID.
The additive diagnostic-aware evaluator entry point leaves existing public error
struct literals and legacy instantiation methods intact.

Frontend failures retain the complete boxed protocol diagnostic. Linker failures retain
source and expanded symbol identity: an exact qualified object origin is preferred;
otherwise a validated matching source and macro symbol selects its authoritative
Definition origin. If only logical source identity is available, the diagnostic uses
an explicitly documented zero-width byte-0 location rather than fabricating precision.
Successful linking retains only a vector of Arc unit handles for error conversion;
structural validation and streamed object identity comparison run only on failure.
