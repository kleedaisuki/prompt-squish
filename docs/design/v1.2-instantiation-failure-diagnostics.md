# Source-qualified instantiation failure diagnostics

Date: 2026-10-01. Status: implemented; hosted integration verification pending.
Related: `ir-model.md` sections 4.1, 7.2 and 7.4; `v1.2-verified-runtime.md`;
`../performance/v1.2-core-remediation.md`.

## Observed defect

Hosted native run 36821935068 (`44979dc`) rejects a recursive SOPack macro with RUN013,
but the host converted `InstantiateError` into Display text only. The action error became
MGB073 with no primary span, related locations or relocated `lib.xml` provenance. Static
origin IDs and the dynamic frame chain already existed in the evaluator; presentation lost
them after its private machine was destroyed. A frame ID alone cannot reconstruct an actual
invocation chain from the linked definition graph.

## Compatibility and evidence API

The public `InstantiateError` fields and `Instantiator::instantiate` signature are unchanged.
An additive `instantiate_with_diagnostics` returns `InstantiationFailure { error, frames }`.
Its frames are an immutable boxed slice, keeping the new failure return type compact without
boxing or changing the existing error. Each `InstantiationFrame` includes the actual frame
ID/identity, optional call origin, and
entry-root or macro-declaration origin. Frames follow the legacy error's actual parent chain
from entry to failing caller. A refused next invocation does not fabricate a frame; completed
sibling/child frames are not appended to that chain. Repeated recursive invocations retain
distinct IDs even when their declaration and call origins coincide.

The private machine runs through a mutable borrow rather than consuming itself, allowing
only the diagnostic-aware error branch to copy these minimal fields before destruction.
Success transfers the same output arenas via `mem::take`; there is no per-operation diagnostic
collection or additional successful frame copy. Budget accounting, evaluation order, trace,
output, stable error codes and original error origins/IDs are unchanged. No argument values,
partial document or fabricated successful trace are exported as failure evidence. Errors
before a machine/frame exists or without dynamic chain context carry an empty frame list.

`LinkedProgram::resolve_origin` resolves exactly `(ObjectDigest, OriginId)` against retained
unit objects, the original origin-table row, its `SourceRef`, and that unit's source archive.
It returns that archive record's logical `SourceKey` and half-open payload-relative UTF-8
span, not the unit header's default key or a provider-name guess. Unknown/ambiguous object
labels, unknown local table IDs and invalid span bounds return None. Ambiguous legacy raw
asserted object labels cannot select an arbitrary first unit. Prepared programs derive exact
object identities from their sealed persistence receipts.

Source spans are relative to bytes after the optional BOM; validation bounds use
`exact_bytes.byte_len - bom_len` and resolution never adds the BOM offset. Host adaptation
maps the exact logical key into its portable diagnostic URI. The runtime bridge owns conversion
to protocol Diagnostic primary/related spans; the manager preserves that typed diagnostic on
ActionFailed instead of replacing it with MGB073 presentation text. Existing error Display
text remains available independently of structured evidence.

## Regression contracts

- A real recursive compiled module is rebound under a kind-5 Project library source ending
  `_providers/frozen-provider/lib.xml`. RUN013 must match the old error exactly; the retained
  three-frame chain resolves its first call to the caller entry and subsequent call/definition
  origins to the relocated library key. Dynamic recursive frame IDs remain distinct.
- Ordinary success returns identical complete output. Depth/output/pre-machine budget and
  invalid-argument failures match every legacy error field, and diagnostic frame IDs match
  the selected chain rather than all partial machine frames.
- Resolution checks exact object ownership, local table bounds, unknown/ambiguous objects,
  an origin pointing to a different SourceArchive record than the unit header, and a span at
  the post-BOM payload boundary. These tests do not substitute guessed filesystem paths.
- The hosted process regression must additionally prove actual CLI JSONL contains RUN013,
  a primary relocated lib.xml source and useful caller/declaration related locations.

Only rustfmt and whitespace/static checks were run locally. No local Cargo/npm or commits
were performed; native compiler/runtime/manager/event integration requires GitHub Actions.

## Grounding

The repository IR contract explicitly defines source-qualified diagnostic origins and dynamic
frame IDs, and forbids fabricated provenance. LLVM's
[diagnostics and source-location design](https://clang.llvm.org/docs/InternalsManual.html#diagnostics)
likewise separates structured source locations from rendered diagnostic prose. The standard
[Rust Error contract](https://doc.rust-lang.org/std/error/trait.Error.html) permits retaining a
structured underlying error rather than reducing it to Display. The build-observation model
in peer-reviewed [Build Systems a la Carte, ICFP 2018](https://www.microsoft.com/en-us/research/publication/build-systems-la-carte/)
provides context for treating reusable execution outcomes separately from scheduling; this
project's stronger observation contract explicitly includes structured diagnostics and budget
behavior, not only successful product bytes. None of these references proves this patch correct;
the exact error/full-output regressions and actual hosted CLI evidence are the acceptance test.
