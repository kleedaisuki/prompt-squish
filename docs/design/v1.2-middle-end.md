# v1.2 source-preserving middle end

Status: implemented session representation in `crates/squish-link/src/middle.rs`.
Integration owner: compiler/linker pipeline. Related authority: `ir-model.md`.

## Boundaries

```text
DSL bytes
  -> front end: RelocatableUnitIr (portable semantic arenas + source attachments)
  -> middle end: OptimizedUnit (unchanged unit + proven facts + compiled regex pool)
  -> linker: linked definitions / operation-target relocation
  -> instantiation: argument-dependent execution + complete expansion provenance
  -> backend: prompt / reproducible pack / reusable sopack
```

The middle end is not a renamed evaluator. It performs context-free computations once,
before invocation: literal regex decisions and named-capture ranges, literal-only scalar
region concatenation, and regex compilation. The evaluator consumes these facts while
retaining dynamic frames, invocation arguments, file bindings, capture scope and budgets.
The linker owns cross-unit definition resolution; the middle end must never distinguish
a unit supplied by local files from an immutable SOPack dependency.

`MiddleEnd::optimize(RelocatableUnitIr) -> Result<OptimizedUnit, MiddleError>` validates
its input before indexing any arena. Errors preserve an IR field path. Regex compilation
errors identify `header.regexes[index]`. Validation is retained for all operations, including
statically unselected branches: optimization must not hide malformed cached/dependency IR.

## Representation and invariants

| Representation | Contents | Lifetime / portability |
| --- | --- | --- |
| `RelocatableUnitIr` | Original IDs, operations, source records, attachments, interfaces and pools | Persistable; suitable for project cache and SOPack |
| `OptimizedUnit.static_matches` | `OpId -> {matched, capture byte ranges}` | Session analysis; reproducible from the portable unit |
| `OptimizedUnit.static_scalars` | `RegionId -> {exact text, ordered OpId byte segments}` | Session analysis; conservative literal-only subset |
| `OptimizedUnit.regexes` | Compiled engine objects in original regex-pool order | Session-only; never serialize engine memory across devices |
| `OptimizationStats` | Deterministic operation, compiled pattern, branch and scalar counters | Available for optional pipeline telemetry |

Every arena ID and every portable byte-level semantic value is retained. There is no
pool insertion, remapping, source rewriting, or removal of a macro call. This is especially
important when a SOPack macro evaluates an asset: its original owning unit and relocated
source identity must remain the origin of the asset lookup, not the calling entry.

Capture values are represented as UTF-8 byte ranges into the original literal. An optional
capture that did not participate remains absent, rather than becoming an empty string.
This preserves the evaluator's inherited capture environment. A regex with no declared
captures uses `is_match` rather than allocating capture machinery. Matched and unmatched
operations remain distinguishable even when both have empty capture maps.

Literal-only scalar facts are computed only for regions referenced by `RenderText` scalar
arguments, avoiding duplicate text allocation for ordinary prompt/module bodies. They retain
a segment for **each** contributing operation, including empty literals. The evaluator
reconstructs the same operation-level
source mappings, budget charges and substitution trace; replacing `RenderText` with an
unqualified string would lose those semantics. The existence of a scalar fact does not
authorize omitting trace construction. Control operations, dynamic bindings, calls,
comments, elements, assets and slots are not folded into a scalar fact.

## Costs and deliberate limits

- Pool compilation occurs once per optimized unit/session, not once per macro expansion.
- Operation scanning is flat and nonrecursive; literal scalar analysis needs no fixed-point
  iteration, global call graph or stack-sensitive traversal.
- Each scalar fact is at most 1 MiB; total materialized scalar text per unit is at most 8 MiB.
  Larger regions remain executable IR. These optimization limits are **not** runtime limits
  and cannot reject a previously valid program or change its result.
- Scalar preflight verifies operation kinds and sizes before allocating text or segments.
- `BTreeMap` fact indexes preserve deterministic iteration and avoid process-local hashing
  affecting inspection or future serialization policy. Compiled regexes use dense pool IDs.

Fresh linking runs the middle end on owned unbound reachable units before symbol binding,
then moves each `OptimizedUnit` into `LinkedProgram::reconstruct_optimized`; cached image
hydration reconstructs device-local facts once. It does not reoptimize the fresh path.
Linked-time dense `(unit_slot, local_def)` tables provide constant-time definition lookup
instead of a linear scan on every macro invocation. Include edges are validated but remain
separate linked subprograms, preserving independent macro namespaces for included entries.

No whole-program macro inlining is claimed. Inlining that discards invocation frames would
change expansion-depth/expansion-count budgets and diagnostics. Cross-unit optimizations
must retain those obligations, even when final prompt bytes would be identical.

## Verification and discriminating next measurements

Focused tests in `middle.rs` cover Unicode capture byte ranges, absent optional groups,
captureless success versus failure, literal segment provenance (including empty strings),
refusal to speculate on bindings, exact size limits, and the aggregate materialization limit.
Repository CI owns compiling and executing the integrated tests; local formatting does not
constitute test execution evidence.

The highest-value integration comparison is an entry repeatedly invoking a macro with a
literal regex, versus the same macro with argument-dependent regex input. Compare complete
document **and trace**, not just prompt bytes. Use separate startup/small-batch and repeated
invocation measurements. A large pattern pool with only one reachable pattern discriminates
whether eager session compilation needs demand-driven refinement; no unmeasured throughput
or startup improvement is asserted here.

## External grounding

The production regex implementation explicitly recommends compiling once and reusing a
pattern, and documents Unicode-safe byte offsets. This directly motivates the session pool
and capture-range representation: [regex official API](https://docs.rs/regex/latest/regex/struct.Regex.html).

MLIR distinguishes analysis results, passes and preserved analyses. The same boundary is
useful here without importing a heavyweight generic pass framework: unchanged portable IR
keeps source facts valid while a higher representation stores execution-specific facts.
See [MLIR pass infrastructure](https://mlir.llvm.org/docs/PassManagement/).

Conditional constant propagation combines value facts with branch reachability; our literal
regex outcomes are a deliberately narrow, decidable instance, not a claim of full sparse
conditional constant propagation. The peer-reviewed foundation is Wegman and Zadeck,
*Constant Propagation with Conditional Branches*, ACM TOPLAS 13(2), 181–210 (1991), available
from the authors' institution: [Brown technical report](https://cs.brown.edu/research/pubs/techreports/reports/CS-91-22.html).

Recent multilevel-IR research illustrates the value of placing domain decisions at the right
representation rather than forcing every optimization into one universal form. HEIR applies
this to homomorphic encryption, not prompt compilation; it is an architectural analogy, not
performance evidence for this project: [HEIR (2025)](https://arxiv.org/abs/2508.11095).
