## 修复机制，而不是改写发布历史 / Repair mechanisms, not release history

1.2.1 是针对 1.2.0 编译、归档和存储路径的修复版本。1.2.0 的标签、发布页和既有产品仍保留其历史身份；精确源码检查点已通过托管验证；**合并后的精确主分支门禁与实际发布仍待完成，不表示所有场景更快或版本已发布**。

Version 1.2.1 repairs compiler, archive and storage mechanisms introduced in
1.2.0. The 1.2.0 tag, release page and existing artifacts retain their
historical identity. The exact source checkpoint passed hosted verification;
**the exact post-merge main gate and publication remain pending. This is not a
claim that every workload is faster or publication is complete**.

### 保持来源、展开帧与资源预算 / Preserve sources, frames and budgets

中端（Middle end）优化保留源码位置、宏调用帧和资源预算，而不是仅比较最终提示词 bytes。修复重点是把可共享的常量事实与不可合并的执行身份分开：重复调用仍拥有独立诊断与预算计数，缓存或预计算不能静默跳过这些语义义务。

Middle-end optimization preserves source positions, invocation frames and
resource budgets, not merely final prompt bytes. Shared constant facts remain
separate from execution identities: repeated calls retain independent
diagnostics and budget costs; caching and precomputation must not silently
skip those obligations.

重复字面量和运行期字符串在传递与捕获时共享已有内容，同时独立保留每次选择的来源证据；多个片段拼接时仍按需物化可见文本，并不承诺拼接永远零复制。用户无需改写 XML 或参数；公共字符串接口、逻辑字节预算和诊断顺序不变。该实现已经精确源码托管验证，测量适用范围见下文。

Repeated literals and runtime strings share existing content during passing
and capture, retaining each selection's own provenance. Concatenating multiple
fragments still materializes visible text when necessary; concatenation is not
promised to be universally zero-copy. XML and arguments need no rewrite:
public string interfaces, logical byte budgets and diagnostic ordering remain
unchanged. The exact source passed hosted validation; measurement scope is below.

pack 的重复构建与共享结果按完整文档、跟踪证据和资源指令共同匹配。两个同样没有 XML 输出的 pack 可能包含不同资源；只比较文档不能证明它们是同一产品。SOPack 装载后先验证整个归档的结构、源码与导入，再选择本目标实际引用的预编译单元。未引用的本地源码仍须遵守严格检查，不能借此隐藏错误。

Pack reuse matches document, trace and archive-directive identity together.
Two packs with equally empty XML output can contain different assets, so
document equality alone is not product equality. A SOPack is structurally
validated, including its sources and import bindings, before selecting the
precompiled units actually referenced by the target. Unreferenced local
sources remain subject to strict validation; pruning is not a way to hide
malformed local files.

求值失败保留真正来源记录的位置和实际调用链，而不是从默认单元头或提供者名称猜测来源。SOPack 中递归宏的诊断使用重定位后的库内路径；重复调用具有独立帧身份。现有错误码和显示文本保持不变，结构化诊断（Structured Diagnostics）附加主位置、相关位置和调用链，不导出参数值或部分失败产品。

Evaluation failures retain the actual source record and invocation chain,
not a guessed unit-header location or provider name. Recursive SOPack macros
diagnose relocated library paths, and repeated calls retain distinct frame
identities. Existing error codes and display text remain unchanged; structured
diagnostics add primary/related locations and real call-chain evidence without
exporting argument values or a partially failed product.

### 可移植编译库与安全归档读取 / Portable libraries and safe archive reading

SOPack 内部提供者身份基于内容、绑定关系和引用拓扑，而不基于生产者检出目录。新的归档读取路径直接验证 ZIP 的本地记录、中央目录和结束记录，不为了验证再构造完整归档。借用读取与共享 bytes 是内部实现变化，不表示开始接受任意第三方 ZIP：安全路径、完整性与资源上限仍需要验证。

SOPack provider identities derive from content, bindings and reference
topology, not the producer's checkout directory. Archive readers validate
local ZIP records, the central directory and the end record directly rather
than rebuilding a complete archive for comparison. Borrowed reads and shared
bytes are internal implementation changes, not permission to accept arbitrary
third-party ZIP: path safety, integrity and resource limits still apply.

### 验证过的不可变快照 / Verified immutable snapshots

内容寻址存储（Content-addressed Storage, CAS）的运行期共享边界使用经过摘要与大小验证的不可变快照。快照可以跨消费者复用，避免重新取得同一 bytes；这不应削弱原有持久化、事务或损坏检测边界。缓存命中的访问记录是建议性元数据，不能冒充构建成功所需的关键事务。

Content-addressed storage uses immutable snapshots verified against their
declared digest and size. Consumers can share a snapshot rather than
reacquiring identical bytes. This must not weaken durability, transactional
publication or corruption detection. Cache-hit recency is advisory metadata,
not a critical transaction establishing build success.

错误缓存键、缺失输出或摘要、大小不符的缓存输出必须在恢复执行状态之前拒绝；既有缓存错误策略可以警告并执行全新构建，这不等于每次都让 CLI 致命失败。派生 CAS 对象即使同样大小也不能因尺寸相同而跳过内容验证：可以重新计算派生数据，同时保持既有、尚未损坏的发布产品。**若已经发布的权威产品文件本身损坏，必须报错，不能把该损坏文件重新采用为有效发布。**

Wrong cache keys, missing outputs and cached-output digest/size mismatches
are rejected before hydration. The established cache-error policy can warn
and rebuild; this does not make every cache rejection a fatal CLI error.
Same-size corruption in a derived CAS object is still detected: derived data
can be recomputed while an existing, uncorrupted published product remains
valid. **Corruption of the authoritative published product file itself is an
error; that corrupt file must never be adopted as a valid publication.**

正常目录准备验证已提交的构建记录和发布文件，不仅为了准备目录而重新装载派生动作输出：其零 CAS 读取边界只针对这一步，**不是承诺热构建零文件读取**。后续动作命中仍要在自身边界验证缓存。SOPack 热命中的已验证单元证明，只能在缓存对象摘要与大小同时匹配本次已冻结的精确编码时共享；其他“有效 IR”不能替代已锁定的库单元。本地缓存对象仍经过公开检查解码器。

Normal catalog preparation verifies the committed build record and published
files without reopening derived action outputs merely to prepare the catalog.
Its zero-CAS-read boundary applies to that preparation step, **not to all
filesystem reads in a warm build**. Later action hits retain their own cache
verification. A warm SOPack unit proof is shared only when the verified cached
blob's digest and size match the exact frozen encoding for this invocation;
some other valid IR cannot substitute for a locked library unit. Local cached
objects still pass the public checked decoder.

## 兼容性与升级说明 / Compatibility and upgrade

- 用户清单、XML 命名空间和既有 CLI 工作流不因内部优化而改名；`.prompt`、`.pack`、`.sopack` 的角色不变。
  Public manifests, the XML namespace and existing CLI workflows are not
  renamed for internal optimization; product roles remain unchanged.
- 私有缓存身份与公共归档格式必须分开讨论。不要编辑内部缓存目录以模拟迁移，不要在既有锁定身份下替换 SOPack bytes。
  Private cache identity and public archive format are separate contracts.
  Do not edit private cache files to simulate migration or replace SOPack
  bytes under an existing lock pin.
- 优化不会在查询时改写输入 SOPack 或锁文件。已有归档 bytes 和 SHA-256 锁定摘要保持不可变；取得依赖与冻结源码之间的内容漂移仍会被拒绝。项目 CAS 的拥有边界仍在项目内。
  Optimization does not rewrite input SOPacks or lockfiles during lookup.
  Existing archive bytes and SHA-256 pins remain immutable, and drift between
  dependency acquisition and source freezing is still rejected. CAS ownership
  remains project-local.
- schema-1 的规范 SOPack 读取契约接受既有 1.2.0 归档；读取后重写单一已重定位归档时，保留已有 `_providers` 名称及规范容器 bytes，不静默迁移公共库命名空间。该兼容契约已通过源码检查点验证，实际发布仍需主分支门禁。
  The canonical schema-1 reader accepts existing 1.2.0 SOPacks. Rewriting a
  single already-relocated archive retains its `_providers` names and
  canonical container bytes rather than silently renaming public libraries.
  This contract passed source-checkpoint verification; publication still requires
  the exact main gate.
- 新构建的多提供者库使用改进的身份算法，可能与 1.2.0 生产者生成不同 bytes。公共 IR 的线格式与摘要语义不因此改动；私有后端缓存身份独立更新，避免把旧动作结果误认为新编码。
  Newly built multi-provider libraries use revised identity semantics and
  may differ in bytes from a 1.2.0 production. Public IR wire formats and
  digest semantics are unchanged; private backend cache identity evolves
  separately so old action results are not mistaken for new encodings.

## 验证与性能证据 / Verification and performance evidence

精确源码 `388f3640252d71fa1d40514a4775beff6598bb24` 的 [GitHub Actions 36842734101](https://github.com/kleedaisuki/prompt-squish/actions/runs/36842734101) 已通过质量检查、Linux / Windows / macOS 原生契约测试、站点及完整机制比较。Linux 共 815 项测试、43 个完成组、零失败。**这是源码检查点，不代替随后合并主分支的精确门禁或实际发布。**

[GitHub Actions 36842734101](https://github.com/kleedaisuki/prompt-squish/actions/runs/36842734101)
passed quality, Linux/Windows/macOS native contracts, Site and the full mechanism
comparison for exact source `388f3640252d71fa1d40514a4775beff6598bb24`. Linux
completed 815 tests across 43 groups with zero failures. **This source checkpoint
does not replace the exact post-merge main gate or actual publication.**

测量采用同一托管运行中的固定基线 `1bbf6cd`，该基线已包含来源索引，**不是未经修改的发布版 1.2.0，也不是 1.1.0**。选定的静态长文本样本（16 次展开、64 KiB）累计申请 bytes 从 5,482,073 降为 171,149，额外存活峰值从 2,132,083 降为 99,899；这些是独立分配测量，不是进程总内存或 RSS。完整实例化在该样本的中位延迟比为 0.814，不代表所有标量宏更快。

Comparisons use pinned baseline `1bbf6cd` within the same hosted run. It already
contains origin indexing: **not untouched released 1.2.0 or version 1.1.0**.
For the selected static long-text fixture (16 expansions, 64 KiB), cumulative
requested bytes decreased from 5,482,073 to 171,149 and peak extra-live bytes
from 2,132,083 to 99,899. These separate allocation measurements are not total
process memory or RSS. Complete instantiation's median latency ratio was 0.814
for that fixture, not a universal scalar speedup.

完整过程比较中的资源 pack 和小范围引用 SOPack 有改善，但启动、小负载热构建、公共 owned 中端控制及部分短键/验证场景仍有混合或负面结果。完整数值、原始样本、预算和语义校验见[精确文本所有权检查点报告](../performance/v1.2-text-owner-checkpoint.md)；[较早 6b 检查点](../performance/v1.2-full-repair-candidate.md)和[初步报告](../performance/v1.2-full-repair-preliminary.md)仅作为历史过程保留，不是本次比值的分母。

Complete-process asset-pack and small-reachable SOPack fixtures improved, while
startup, tiny warm builds, public owned middle-end controls and some short-key
or validation cases remain mixed or negative. See the [exact text-owner checkpoint report](../performance/v1.2-text-owner-checkpoint.md)
for complete results, raw samples, budgets and semantic oracles. The [earlier 6b checkpoint](../performance/v1.2-full-repair-candidate.md)
and [preliminary report](../performance/v1.2-full-repair-preliminary.md) remain
historical records, not the denominator of this run's ratios.
