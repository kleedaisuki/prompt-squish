# xmlsquish 0.3.0

- 发布日期 / Release date: 2026-09-11
- 标签 / Tag: `v0.3.0`
- 最低 Rust 版本（Minimum Supported Rust Version, MSRV）: **1.88**

**宏库负责复用，入口负责产品。** 0.3.0 分离显式入口与宏定义，统一递归展开，并复用编译快照和静态中间表示（Intermediate Representation, IR）。这是破坏性语言更新，不兼容 0.2.0 语法。

**Libraries provide reuse. Entries build the product.** 0.3.0 separates explicit build roots from macro definitions, unifies recursive expansion, and reuses prepared compilation snapshots and static IR. This breaking language release does not support 0.2.0 syntax.

规范 / Normative specification: [0.3.0 DSL](https://xmlsquish.moesegfault.dev/ns/0.3.0/dsl.md).

## 一套清楚的组合模型 / One clear composition model

| 构造 / Form | 0.3.0 契约 / Contract |
| --- | --- |
| `xs:module` | 只组织 import 与宏定义的库 / A library containing imports and macro definitions only |
| `xs:entry` | 独立构建入口，包含导入、参数及产品正文，不是宏 / A separate build root with imports, parameters and product construction; not a macro |
| `xs:macro` | 唯一可展开单位；独立作用域，参数按值传递 / The sole expandable unit, with isolated scope and value-passed inputs |
| `xs:import` | 唯一装载操作，仅接受模块；重复导入按源码身份去重 / The sole loading operation; modules only, deduplicated by source identity |
| `xs:expand` | 唯一递归展开操作，返回有序节点序列 / The sole recursive expansion operation, returning an ordered node sequence |

没有隐式 `main`，没有 `module` 的 `entry` 属性，也没有独立 `fragment` 构造。入口不能被导入或当作宏展开。纯文本返回值可在 `xs:arg` 正文中组合；结构返回值可在 `xs:fill` 中组合。输入先在展开者环境求值，再按值传入独立作用域，不捕获外部变量。递归和字符串计算保留计算完备性；实际执行仍受资源预算约束。

There is no implicit `main`, no module `entry` attribute, and no separate `fragment` construct. Entries cannot be imported or expanded as macros. Text-only returns compose in `xs:arg` bodies, while structural returns compose in `xs:fill`. Inputs evaluate in the expander's environment before being passed by value into an isolated scope without caller capture. Recursion and string computation retain computational completeness; actual execution remains resource-budgeted.

宏库 `greetings.xml` / Macro library:

```xml
<xs:module xmlns:xs="https://xmlsquish.moesegfault.dev/ns"
           xmlns:g="urn:example:greetings">
  <xs:macro name="g:greeting">
    <xs:param name="name"/>
    <Greeting>Hello, <xs:insert get="arg.name"/>!</Greeting>
  </xs:macro>
</xs:module>
```

入口 `hello.xml` / Build entry:

```xml
<xs:entry xmlns:xs="https://xmlsquish.moesegfault.dev/ns"
          xmlns:p="urn:example:greetings">
  <xs:import src="greetings.xml"/>
  <xs:param name="name"/>
  <Prompt>
    <xs:expand ref="p:greeting">
      <xs:arg name="name" get="arg.name"/>
    </xs:expand>
  </Prompt>
</xs:entry>
```

```bash
xmlsquish --arg name=Klee hello.xml
```

`import` 装载定义，但不继承前缀绑定。上例的 `g` 和 `p` 是不同文件中的本地别名，指向同一个命名空间 URI；宏身份仍是 URI 与局部名的组合。完整依赖闭包在执行前冻结、检查和链接，包括未选中的分支。这里提供链接时优化（Link-Time Optimization, LTO）的基础，不宣称已实现 LTO 优化器。

Imports load definitions without inheriting prefix bindings. Here `g` and `p` are local aliases for the same namespace URI; macro identity remains the URI/local-name pair. The complete dependency closure is frozen, checked and linked before execution, including unselected branches. This supports future link-time optimization, but is not an implemented LTO optimizer.

## 从 0.2.0 迁移 / Migrating from 0.2.0

- 将生成最终文档的根改为 `xs:entry`，把可复用宏放入 `xs:module` 库；目录和 glob 扫描会跳过合法库文件，显式编译库文件仍报错。
  Use `xs:entry` for document-building roots and `xs:module` for reusable libraries. Directory/glob discovery skips valid libraries; explicitly compiling a library remains an error.
- 用 `xs:expand` 替换 `xs:call`；将原 `xs:mount` 目标正文提取成显式命名宏，使用 `import` 加 `expand` 组合。删除隐式入口假设，不要制造 `main` 包装。
  Replace `xs:call` with `xs:expand`. Extract former `xs:mount` target bodies into named macros and compose using `import` plus `expand`. Remove implicit-entry assumptions rather than introducing `main` wrappers.
- **最终 `.o.xml` 移除全部属性、命名空间声明及元素前缀，并压缩空白。** 没有属性保留开关，`xml:space` 不能覆盖此产品语义。源码 DSL 属性仍用于编译；`.i.xml` 保留来源诊断信息。
  **Final `.o.xml` removes every attribute, namespace declaration and element prefix, and squishes whitespace.** No attribute-preservation option or `xml:space` override exists. Source DSL attributes still drive compilation; `.i.xml` retains provenance diagnostics.

## 可复用编译与性能 / Reusable compilation and performance

内部 `Compiler::prepare` 一次冻结和链接源码，`PreparedProgram::expand` 使用新参数与预算重复展开；复用不可变静态载荷、转义结果和来源信息序列化，不复用执行帧或完整宏结果。源码变化需重新准备。CLI 仍为各入口独立准备快照；这是内部二进制模块能力，不是新增公共 Rust 库接口。

Internally, `Compiler::prepare` freezes and links once, while `PreparedProgram::expand` runs with fresh arguments and budgets. Immutable static payloads, escaping and source serialization are reused, not execution frames or complete macro results. Reprepare after source edits. CLI entries still prepare independently; this is an internal binary-module capability, not a new public Rust library API.

七个固定微基准的内存中完整编译耗时下降 **17.4%–81.1%**，覆盖微小入口、重复宏、填充转发、递归、属性密集、非重复节点和标量返回组合。测量包含解析、链接、展开、IR 序列化及结果释放，**不包含 CLI 启动、文件 I/O、token 计数和最终空白压缩**。部分准备阶段回归；尚未测量峰值内存，不声称普遍加速或内存下降。小型 GSP 的实际 CLI 波动跨越零，不能据此宣称端到端显著提速。

Seven fixed in-memory full-compilation microbenchmarks show **17.4%–81.1%** lower elapsed time, covering tiny entries, repeated macros, fill forwarding, recursion, attribute-heavy content, unique nodes and scalar-return composition. Timing includes parsing, linking, expansion, IR serialization and result destruction, **excluding CLI startup, filesystem I/O, token counting and final whitespace squishing**. Some preparation-only phases regress. Peak memory is unmeasured; no universal speedup or memory reduction is claimed. Small-corpus GSP CLI differences cross zero and do not establish material end-to-end acceleration.

原始样本、硬件环境、基线、取舍与复现命令见 [性能报告 / Performance report](https://github.com/kleedaisuki/prompt-squish/blob/v0.3.0/docs/performance/README.md)。

## 边界与验证 / Boundaries and verification

默认预算保持为深度 `1024`、展开次数 `100000`、每个受检输出缓冲区 `67108864` 字节。输出字节预算不是进程总内存上限。默认加载器只支持本地 `file:` URI，不是文件访问沙箱；仅编译可信源码，或使用外部文件权限与进程隔离。

Defaults remain depth `1024`, expansions `100000`, and `67108864` bytes per guarded output buffer. Byte guards are not a total process-memory limit. The default loader supports local `file:` URIs only and is not a filesystem sandbox; compile trusted sources or apply external filesystem and process isolation.
