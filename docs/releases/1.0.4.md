## 项目拥有自己的构建状态 / The project owns its build state

xmlsquish 的提示词依赖很小，也没有 C/C++ 系统库那样值得跨项目共享的传统生态。
1.0.4 因此移除机器全局缓存模型，把产品、依赖源码缓存、内容寻址存储
（Content-Addressed Store, CAS）、动作索引与恢复元数据统一收进当前项目或工作区的
`target/xmlsquish`。复制项目不会再暗中继承另一台机器的状态，删除项目也不会留下用户级
xmlsquish 缓存。

Prompt dependencies are small and do not resemble the traditional C/C++ system-library ecosystem
where cross-project machine caches carry clear value. Version 1.0.4 therefore removes the
machine-global cache model. Products, dependency sources, the content-addressed store (CAS), action
index, and recovery metadata now live together under the current project or workspace's
`target/xmlsquish`. Copying a project no longer silently inherits another machine's state, and
deleting it leaves no user-level xmlsquish cache behind.

```text
target/xmlsquish/
├── artifacts/                  # stable .prompt products and optional IR/debug outputs
├── cache/
│   ├── cas/
│   ├── actions.sqlite3
│   └── sources/
├── metadata/
│   ├── layout.json
│   ├── publications/
│   └── catalog/
└── work/                       # same-filesystem, non-authoritative staging
```

产品定位符仍是稳定的项目相对路径，但现在显式包含 `artifacts/`，例如
`target/xmlsquish/artifacts/chat.prompt`。`cache/`、`metadata/` 与 `work/` 是工具管理的实现
目录，自动化不应把其中的散列、journal 或数据库模式当作 API。自定义工作区
`target-dir` 时，同样的布局位于该目录，而不是用户主目录。

Product locators remain stable project-relative paths but now explicitly include `artifacts/`, for
example `target/xmlsquish/artifacts/chat.prompt`. `cache/`, `metadata/`, and `work/` are tool-managed
implementation directories; automation must not treat their hashes, journals, or database schemas
as APIs. A custom workspace `target-dir` moves this complete layout together instead of redirecting
state into the user's home directory.

## 简单而完整的清理 / Simple, complete cleaning

`xmlsquish clean` 现在删除整个项目本地 `target/xmlsquish` 构建根。下次构建从受版本控制的
源码、清单和锁文件重建它。不存在“清理产品但保留机器全局健康缓存”的特殊分支，也不再
需要推理其他项目是否引用某个缓存条目。

`xmlsquish clean` now removes the complete project-local `target/xmlsquish` build root. The next
build reconstructs it from version-controlled sources, manifests, and the lockfile. There is no
special branch that cleans products while preserving a healthy machine-global cache, and no need to
infer whether another project references a cache entry.

构建根的同父目录可能存在维护锁 `.<leaf>.xmlsquish.lock`，并在 clean 恢复期间短暂存在
`.<leaf>.xmlsquish.clean.json` 与 trash 目录。它们使 clean 能原子分离完整根，同时等待
正在使用 SQLite WAL 或发布状态的 build/inspect 进程；它们不是跨项目缓存。

The build root's parent may contain a `.<leaf>.xmlsquish.lock` maintenance lock and, during clean
recovery, a transient `.<leaf>.xmlsquish.clean.json` plus trash directory. They let clean atomically
detach the complete root while waiting for build/inspect processes that use SQLite WAL or
publication state; they are not cross-project caches.

```console
$ xmlsquish clean
$ xmlsquish build --offline  # succeeds only when required project-local sources are available
```

这是有意的破坏性迁移：1.0.4 不读取或迁移旧的用户级缓存、`.xmlsquish/cache` 或分离的
manager storage。需要保留的构建产品应在升级前复制到构建根之外；否则直接重新构建。

This is an intentional breaking migration. Version 1.0.4 neither reads nor migrates legacy
user-level caches, `.xmlsquish/cache`, or separate manager storage. Copy any build products that
must be retained outside the build root before upgrading; otherwise, rebuild them.

## 受门禁保护的发布 / Gated releases

CI 使用 Rust 1.88 和锁文件，在 Linux、Windows 与 macOS 上构建并运行完整 workspace 的
全部目标测试；Linux 质量作业另外执行格式、Clippy、文档测试、架构检查和发布脚本自测。
标签发布在开始六平台原生构建前，先验证根包版本、锁文件版本、标签、更新日志和本页完全
一致。每个平台随后执行 release 测试及安装后 CLI 冒烟测试；只有所有平台成功，聚合作业
才会创建或完成 GitHub Release。

CI uses Rust 1.88 and the lockfile to build and run every workspace target on Linux, Windows, and
macOS. The Linux quality job additionally checks formatting, Clippy, documentation tests,
architecture rules, and the release automation itself. Before six native builds begin, a tag release
verifies that the root package, lockfile, tag, changelog, and this page agree exactly. Each platform
then runs release tests and installed-CLI smoke tests; only the complete matrix permits the
aggregation job to create or finish the GitHub Release.

## 安装 / Install

从 [GitHub Release](https://github.com/kleedaisuki/prompt-squish/releases/tag/v1.0.4) 下载平台
归档和同次发布的 `SHA256SUMS`，先核对准确文件名对应的 SHA-256，再解压并把可执行文件
加入 `PATH`。

Download the platform archive and `SHA256SUMS` from the
[GitHub Release](https://github.com/kleedaisuki/prompt-squish/releases/tag/v1.0.4). Verify the
SHA-256 row for the exact filename before extracting the executable and adding it to `PATH`.

| 系统 / OS | 架构 / Architecture | 资产 / Asset |
|---|---|---|
| Windows 10 / 11 | x86-64 | `xmlsquish-1.0.4-x86_64-pc-windows-msvc.zip` |
| Windows 10 / 11 | ARM64 | `xmlsquish-1.0.4-aarch64-pc-windows-msvc.zip` |
| Linux · glibc ≥ 2.35 | x86-64 | `xmlsquish-1.0.4-x86_64-unknown-linux-gnu.tar.gz` |
| Linux · glibc ≥ 2.35 | ARM64 | `xmlsquish-1.0.4-aarch64-unknown-linux-gnu.tar.gz` |
| macOS ≥ 11 | Intel | `xmlsquish-1.0.4-x86_64-apple-darwin.tar.gz` |
| macOS ≥ 11 | Apple Silicon | `xmlsquish-1.0.4-aarch64-apple-darwin.tar.gz` |

也可以从不可变标签源码安装：

You may instead install from the immutable source tag:

```console
cargo install --git https://github.com/kleedaisuki/prompt-squish --tag v1.0.4 --locked
```

当前二进制未做代码签名（code signing）或 Apple 公证（notarization）。`SHA256SUMS` 证明
下载字节的完整性，不单独证明发布者身份。

The binaries are unsigned and not Apple-notarized. `SHA256SUMS` establishes downloaded-byte
integrity; by itself it does not establish publisher identity.

## 兼容性边界 / Compatibility boundary

- 机器协议仍为 `3.1`；已有事件与结果字段未因存储搬迁而改变。
- XML DSL 命名空间、清单格式、产品格式、退出码与 Rust 1.88 最低支持版本不变。
- 旧全局缓存、旧 `source.cache-root` / `manager.storage-root` 配置键和旧磁盘状态不兼容，也不会自动迁移。
- 仓库和二进制不发布到 crates.io。

- The machine protocol remains `3.1`; existing event and result fields are unchanged by storage
  relocation.
- The XML DSL namespace, manifest format, product formats, exit codes, and Rust 1.88 minimum
  supported version remain unchanged.
- Legacy global caches, legacy configuration keys, and legacy on-disk state are incompatible and
  are not migrated.
- The workspace and binaries remain unpublished on crates.io.
