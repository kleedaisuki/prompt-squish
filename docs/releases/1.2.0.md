## 从提示词到可分发编译单元 / From prompts to distributable compilation units

1.2.0 将构建模型从 module / entry 扩展为四种显式源码根。模块负责定义，入口负责提示词，pack 负责交付一个含提示词和原始资源的归档，SOPack 负责分发可复用编译库。**SOPack 不是成品，也不是复制项目缓存。**

Version 1.2.0 extends module/entry with two explicit roots: pack for final
delivery and SOPack for reusable compiled libraries. **A SOPack is neither a
final product nor a copied project cache.**

| 源码根 / Root | 产品角色 / Role | 构建输出 / Output |
| --- | --- | --- |
| `xs:entry` | 构造一个提示词 / Construct a prompt | `.prompt` |
| `xs:module` | 定义宏；由其他单元导入 / Define macros for import | 编译依赖 / Compiled dependency |
| `xs:pack` | 聚合入口与原始资源 / Aggregate entries and raw assets | `.pack` |
| `xs:sopack` | 保存模块、IR、宏、资源及元信息 / Preserve modules, IR, macros, assets and metadata | `.sopack` |

### 字节保真资源与入口包含 / Byte-preserving assets and entry inclusion

`xs:asset` 保存完整文件 bytes，不将代码、图片或静态资源当作 XML 解析，也不对其做提示词空白压缩。`xs:include` 包含一个 entry，不能包含 module。SOPack 可以导入模块并声明宏、保存资源，但不能使用 include 收集成品。

`xs:asset` preserves complete file bytes without XML parsing or prompt
whitespace processing. `xs:include` includes an entry, never a module.
SOPack imports modules and can define macros and assets, but cannot include
final entries.

### 可复现与可重定位 / Reproducibility and relocation

pack / SOPack 是可复现 ZIP（Reproducible ZIP）：相同有效输入得到相同归档 bytes，而不是仅解压后内容相同。归档路径、条目顺序和时间戳采用确定性策略。SOPack 对所有源码身份进行重定位（Relocation）；诊断位置与宏内的资源引用随库一起携带，不依赖生产者的绝对路径。消费者通过包依赖 add / remove 生命周期接入不可变 SOPack，链接器无需区分本地源码和库中模块。

Pack and SOPack are reproducible ZIP containers: identical effective inputs
produce identical archive bytes. Deterministic names, ordering and timestamps
avoid host-specific archive differences. Source identities are relocated so
diagnostics and macro-owned asset references survive moving the library to a
different device. SOPack dependencies are immutable and use the ordinary
add/remove lifecycle; the linker does not special-case their origin.

## 显式编译阶段 / Explicit compiler stages

```text
squish DSL → front end → IR → middle-end optimization
                             ↓
                  linker + link-time optimization
                             ↓
                  prompt / pack / sopack backend
```

前端（Front end）负责解析和降低到中间表示（Intermediate Representation, IR）；中端（Middle end）尽可能完成编译期计算和宏展开；链接器（Linker）聚合被引用的编译单元，并保留下一层仍需的信息；后端（Backend）决定提示词空白处理或 ZIP 分发。资源 bytes 与源码归属不应在阶段之间丢失。

The front end lowers the DSL to IR; the middle end performs available
compile-time evaluation and macro expansion; the linker aggregates referenced
units and optimizes their linked representation; the backend chooses prompt
whitespace processing or ZIP distribution. Each stage preserves source
ownership and opaque asset bytes needed by the next stage.

## 遥测与迁移 / Telemetry and migration

端到端遥测（Telemetry）和跟踪（Tracing）默认关闭，按需开启。运行证据保存在项目构建根的 `metadata/`，可跨运行分析；它们不应成为 pack / SOPack 的非确定性输入。请不要将 trace 中的路径、参数或诊断直接视为可公开数据。

End-to-end telemetry and tracing are disabled by default and explicitly
enabled when needed. Evidence persists across runs in project build metadata,
outside the deterministic product. Trace paths, arguments and diagnostics may
contain private information; review records before sharing them.

本版本有意不保证旧派生缓存可读。若遇到旧缓存布局，执行 `xmlsquish clean` 后重建；这会删除项目构建根，离线重建需要重新具备所需依赖。缓存仍属于项目；**跨设备分发请使用 SOPack，而不是复制 cache 目录**。不变的 XML 命名空间不表示旧 CLI 已支持新指令；使用新单元的项目需要 1.2.0。

Old derived caches are intentionally not a compatibility contract. Clean and
rebuild when upgrading; cleaning removes project-local build state, so an
offline rebuild requires the dependency inputs to be available again. Use
SOPack—not a copied cache—for cross-device distribution. The stable XML
namespace does not make new directives readable by older CLIs.


```console
xmlsquish --trace=summary build
xmlsquish --trace=events build
xmlsquish --trace=off build
```

`--trace` without a value means `events`; values require `=`.
`XMLSQUISH_TRACE=summary|events|1|true` is the environment fallback; explicit
`--trace=off` overrides it. Summary records command and stage spans; events
also records lifecycle events and diagnostics. JSONL records use
`xmlsquish.trace.v1` and persist at
`<target-dir>/metadata/traces/<invocation>.jsonl`. There is no outbound
transmission. Trace write failures emit `TRACE001` warnings without changing
the command result; review paths and diagnostic payloads before sharing.

## 安装 / Install

从 [v1.2.0 GitHub Release](https://github.com/kleedaisuki/prompt-squish/releases/tag/v1.2.0) 下载平台归档、自带 `SKILL.md` 与 `SHA256SUMS`。按准确文件名校验 SHA-256 后解压，将 `xmlsquish` 加入 `PATH`。Linux 要求 glibc ≥ 2.35，不是 musl 构建；macOS 最低 11.0。发布二进制未签名或 Apple 公证。

Download an archive, the bundled `SKILL.md`, and `SHA256SUMS` from the
[v1.2.0 GitHub Release](https://github.com/kleedaisuki/prompt-squish/releases/tag/v1.2.0).
Verify the exact filename before extracting and placing the binary on `PATH`.
Linux requires glibc 2.35+ (not musl); macOS requires 11+. Binaries are unsigned
and not Apple-notarized.

| 系统 / OS | 架构 / Architecture | 资产 / Asset |
| --- | --- | --- |
| Windows 10 / 11 | x86-64 | `xmlsquish-1.2.0-x86_64-pc-windows-msvc.zip` |
| Windows 10 / 11 | ARM64 | `xmlsquish-1.2.0-aarch64-pc-windows-msvc.zip` |
| Linux | x86-64 | `xmlsquish-1.2.0-x86_64-unknown-linux-gnu.tar.gz` |
| Linux | ARM64 | `xmlsquish-1.2.0-aarch64-unknown-linux-gnu.tar.gz` |
| macOS | Intel | `xmlsquish-1.2.0-x86_64-apple-darwin.tar.gz` |
| macOS | Apple Silicon | `xmlsquish-1.2.0-aarch64-apple-darwin.tar.gz` |

```console
cargo install --git https://github.com/kleedaisuki/prompt-squish --tag v1.2.0 --locked
xmlsquish --version
xmlsquish install-skill --project --dry-run
```

Rust 最低支持版本为 1.88；仓库不发布到 crates.io。测试和发布构建在 GitHub Actions 上执行，使用锁定依赖与缓存；六个平台归档和自带指南由同一版本发布，并提供校验和。性能变化应以 CI 基准证据为准，而不是将一次启动或缓存命中当作全链路加速证明。

Minimum Rust is 1.88; the project is not published to crates.io. GitHub Actions
tests and builds locked dependencies with caching; six native archives and
the bundled guide are published together with checksums. Evaluate performance
using measured CI evidence, not one startup or a warm-cache observation.
