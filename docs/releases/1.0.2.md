- 标签 / Tag: `v1.0.2`
- 机器协议 / Machine protocol: `3.1`

## 可读的构建目录 / A readable build directory

`target/xmlsquish` 现在直接呈现清单声明的稳定产品路径。内部 generation、journal、
current pointer 与内容 hash 已迁入 manager 的项目私有状态；它们不再成为用户查找产物
所必须穿过的目录。既有逻辑 locator 保持不变，所以 1.0.1 的脚本仍可继续使用：

`target/xmlsquish` now materializes the stable product paths declared by the manifest. Internal
generations, journals, current pointers, and content hashes have moved into project-private manager
state, so users no longer traverse them to reach a product. Existing logical locators are unchanged,
and scripts written for 1.0.1 continue to work:

```console
$ xmlsquish build --emit=prompt --emit=ir --emit=debug
$ ls target/xmlsquish
prompt.prompt  ir/  prompt.psdbg
$ xmlsquish inspect artifact target/xmlsquish/prompt.prompt --format=raw
```

`.xsmap`、`*.build.json` 与发布事务状态仍由 typed catalog 使用，但不会物化到产品目录。
构建或恢复会以同一稳定路径幂等更新产品；路径不会包含 target hash 或 generation hash。

`.xsmap`, `*.build.json`, and publication-transaction state remain available to the typed catalog
but are not materialized into the product directory. Builds and recovery idempotently update the
same stable product paths; neither target nor generation hashes appear there.

## `clean`

新增的无参数 `xmlsquish clean` 删除当前项目/工作区的构建产品与项目私有发布状态，并
清理共享依赖缓存中**可证明损坏或已遗弃**的条目。它不会改写清单或锁文件，也不会仅因
当前项目未引用就删除健康的共享依赖；全局 CAS 与 action index 同样保留。

The new argument-free `xmlsquish clean` removes the current project/workspace products and private
publication state, then prunes dependency-cache entries that are **provably corrupt or abandoned**.
It does not rewrite manifests or the lockfile, delete healthy shared dependencies merely because
this project does not reference them, or purge the global CAS/action index.

```console
$ xmlsquish clean
$ xmlsquish build --offline
```

机器输出中的 `clean` 请求与结果是协议 3.1 的可加性扩展（additive extension）。3.0
消费者应忽略未知的可选事件/结果字段；调用新命令的消费者应声明并处理 3.1。

The `clean` request and result are an additive machine-protocol 3.1 extension. Protocol 3.0
consumers should ignore unknown optional events/result fields; consumers invoking the new command
should declare and handle 3.1.

## Agent 入口 / Agent entry point

仓库根目录新增短小的 `SKILL.md`，集中提供真实的 CLI 工作流、`xmlsquish.toml` 配置语法
与 XML DSL 核心语义。Agent 应读取清单和声明式 export/target，而不是扫描文件名或私有
依赖目录来猜测项目结构。

The new root `SKILL.md` is a compact source for real CLI workflows, `xmlsquish.toml` syntax, and the
core XML DSL semantics. Agents should read manifests and declared exports/targets rather than infer
project structure from filenames or private dependency directories.

## 安装 / Install

从 [GitHub Release](https://github.com/kleedaisuki/prompt-squish/releases/tag/v1.0.2) 下载与
平台匹配的压缩包和同次发布的 `SHA256SUMS`。六个原生目标都在对应操作系统上执行锁定
测试与 CLI smoke test 后，才由唯一聚合作业创建 Release。

Download the matching archive and `SHA256SUMS` from the
[GitHub Release](https://github.com/kleedaisuki/prompt-squish/releases/tag/v1.0.2). Each of the six
native targets runs locked tests and a CLI smoke test on its corresponding operating system before
one aggregation job creates the Release.

也可以从标签源码安装：

You may instead install from the tagged source:

```console
cargo install --git https://github.com/kleedaisuki/prompt-squish --tag v1.0.2 --locked
```

当前二进制未做代码签名（code signing）或 Apple 公证（notarization）。请在解压前核对
准确文件名对应的 SHA-256；校验和证明字节完整性，不证明发布者身份。

The binaries are unsigned and not Apple-notarized. Verify the SHA-256 row for the exact filename
before extraction; checksums establish byte integrity, not publisher identity.

## 兼容性与限制 / Compatibility and limitations

- 产品 locator、清单版本、锁定/离线模式、退出码、DSL 命名空间与 Rust 1.88 MSRV 不变。
- 自定义 `[workspace].target-dir` 仍控制产品根；目录必须是工作区内的相对路径。
- `clean` 的共享缓存清理是完整性维护，不是全局健康缓存的可达性 GC。
- 仓库和二进制仍不发布到 crates.io。

- Product locators, manifest version, locked/offline modes, exit codes, DSL namespace, and the
  Rust 1.88 MSRV remain unchanged.
- A custom `[workspace].target-dir` still selects the product root and must be workspace-relative.
- Shared-cache work performed by `clean` is integrity maintenance, not reachability GC for healthy
  global cache entries.
- The workspace and binaries remain unpublished on crates.io.
