## Verdict

No concrete blocking safety or canonical-ZIP acceptance defect was found in this
source snapshot. This is not a compile/test verdict. Producer graph identities
are deliberately changed; schema-1 reader compatibility must not be confused
with acceptance of every input previously accepted by the writer.

## Direct ZIP checks

The previous reader parsed local records, checked CRC, reconstructed the entire
ZIP with the writer, and compared exact bytes. The replacement validates the same
canonical byte grammar directly:

| Boundary | Independently checked correspondence |
| --- | --- |
| Local | Signature; all version/flag/method/date/time fields; zero extra length; equal sizes; exact UTF-8 name; raw ascending order; portable uniqueness and prefixes; body CRC. |
| Central | Exactly one record for each local record in the same order; complete fixed metadata; identical CRC, sizes and name; exact local offset; zero extra/comment/disk/internal attributes; fixed external mode. |
| End | Immediately follows those central records; exact size/start/counts; zero disk/comment fields; exactly EOF. |

There is no accepted prefix, hidden/orphan record, alternative local order,
comment, extra field, descriptor, ZIP64 extension or trailing byte. A coherent
body replacement with both CRCs updated is correctly accepted, rather than
mistaking every mutation for damage. Empty canonical ZIP remains accepted.

Arithmetic additions outside the checked slice helper follow successful slices:
a complete local header bounds `offset + 30`, the name slice bounds its end, the
body slice bounds the next offset; the same argument applies to central/end
advancement. The classic archive-size bound is checked first. No unsafe parsing
or escape from the input lifetime is present.

Writer record bytes are unchanged from HEAD. It reuses each computed CRC and
writes the central directory directly into final output. Owned compatibility
reading copies bodies only after the complete borrowed ZIP has been accepted.
The legacy test oracle freezes the old algorithm, while sharing the unchanged
portable path validator; it is not a fully independent path-policy oracle.

Authored tests compare a binary/UTF-8 fixture and every one-bit corruption with
the old reader, truncate at every position, check coherent changed content,
empty archive, limits, collisions and input aliasing. They remain unexecuted in
this review. Static field-by-field correspondence, not that finite mutation
matrix alone, supports the acceptance assessment.

## Shared bodies, hashing and resource accounting

`SopackPayloadRef` borrows unit arenas/source/asset bytes; path and import metadata
are copied. ZIP descriptors do not own those bodies. Their producer collections
remain alive throughout writing, and returned archive bytes own their content.

The write-local `(pointer,length)` content hash cache is sound for immutable
borrowed slices: all referenced allocations live for that call; equal live
address/length means equal bytes (empty slices also have identical content).
There is no cross-call address reuse cache. CRCs still validate actual transport
bodies independently of this BLAKE3 cache.

On shared read, each declared digest is checked against its actual archive body
before its first `Arc<[u8]>` creation. Later aliases reuse that immutable body,
not unchecked bytes. The files map still retains the unique authoritative member
until every binding has been handled. Distinct digests cannot refer to the same
file name. Owners are relocated identically to unit/source/import identities;
asset bindings remain keyed by defining source, not caller location.

Expanded source-plus-owner-asset bytes and binding counts remain bounded even
though physical storage is deduplicated. Transport bytes/content/member count,
8 MiB manifest bound, canonical manifest serialization, closure completeness,
exact diagnostic attachments and undeclared-member rejection remain enforced.
The owned wrapper intentionally expands shared assets back into independent
Vec bodies and must not be used as evidence of zero-copy owned output.

## Provider graph correctness and compatibility boundary

The iterative implementation is Kosaraju-style SCC decomposition, not Tarjan's
algorithm. It avoids recursive stack growth. Distinct dependency components are
processed only after their targets, and every component/member fingerprint uses
content seeds, labelled import edges and content-derived member ordinals, never
host indices or checkout paths. Unique seeds avoid refinement; cyclic topology
and member count remain encoded in the component stream. Tied cyclic seeds use
monotone partition refinement (the old color is included), terminating when all
members are distinguished or no further split occurs.

The new namespace domain is explicit (`sopack-provider-scc-v3`). The reader does
not recompute provider paths and accepts the existing schema-1 format. Rewriting
a decoded archive has one relocated package group; the single-group fast path
keeps old `_providers/...` path spelling instead of applying a new fingerprint.
Exact old/new provider fingerprint equality is neither achieved nor claimed.

There is a deliberate producer acceptance narrowing worth preserving explicitly:
a two-provider equal-seed symmetric cycle can be accepted by HEAD if one provider
is the explicit packaging root. HEAD's G rounds give both providers the same
color, but the root path stays unprefixed while the other provider receives
`_providers/<color>/<path>`, so the final path collision guard does not reject it.
The new SCC refinement rejects that ambiguous component before root path
selection. The design explicitly declares ambiguity rejection; therefore this
is recorded as an acceptance-policy boundary, not disguised as reader
incompatibility or a newly demonstrated blocker. If compatibility with every old
writer input is required, add this exact root/foreign fixture and revise the
ambiguity policy rather than using host paths to break ties.

## Complexity and remaining evidence

The removal of G global rounds is supported by source for isolated/acyclic and
unique-seed cyclic graphs: SCC traversal is O(G+E), followed by ordered map/set
operations, seed/content processing and per-node edge sorting. It is not a claim
that the complete writer is strictly linear. Tied cyclic components retain up
to component-size refinement rounds; the docs disclose that separate tail.
`fingerprints` stores reverse edges and condensation metadata in O(G+E) space.

Borrowed ZIP read allocations contain name/set/descriptor metadata, not payload
D; owned read adds body ownership. Name comparisons and prefix-set lookups have
string-length and logarithmic factors, so the convenient O(D+L+N log N) summary
should not be read as an exact worst-case bound for long common-prefix paths.
No measured latency/allocation improvement is established by this review.

Hosted CI still needs compilation, native authored regressions, shared asset
pointer identity/fanout probes, old schema-1 fixtures, new-writer/old-reader
acceptance, and provider permutation/topology/tie tests. In particular the
old-codec oracle currently covers ZIP, not the entire previous SOPack writer.

## External contract anchors

[PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)
defines the local/central/end record layout; the application intentionally
accepts a narrower canonical subset. [Reproducible Builds archive guidance](https://reproducible-builds.org/docs/archives/)
anchors ordering and metadata normalization. [Tarjan, SIAM Journal on Computing
1972](https://epubs.siam.org/doi/10.1137/0201010) anchors classical linear graph
traversal/decomposition; it does not prove this implementation's entire ordered
fingerprinting pipeline linear, nor solve general graph canonicalization.

## Follow-up: root-role correction reviewed

The archive owner accepted the concrete root/foreign symmetric-cycle boundary
and added a `root` versus `provider` role field to the versioned base seed
(`sopack-provider-seed-v3`). Inspected that change independently: the role is
selected from the explicit/inferred logical packaging root, not a filesystem
identity. It distinguishes the two formerly equal seeds; both nodes in the
two-node root-anchored cycle therefore get canonical ordinals without ambiguous
refinement. The rare demonstrated old-writer rejection path above is resolved
at source level. Entirely symmetric foreign SCCs still have the documented
ambiguity boundary; no old-reader rejection follows from the new namespace.

The newly added shared-asset pointer test verifies Arc aliasing and re-encoding,
but its initial 600-byte limit fails at ZIP physical content before reaching the
expanded alias limit. Requested a discriminating fixture: large shared body,
limit between unique physical content and expanded owner bytes, explicit ZIP
acceptance followed by shared-SOPack rejection. This is a test-evidence issue,
not a demonstrated production limit failure.
