`../performance/v1.2-store-orchestration-audit.md`,
`pack-sopack-review.md`, and their supporting core/archive/ZIP/runtime documents.

A row is complete only when its contract-preserving implementation or explicitly
evidenced necessity decision is independently inspected, discriminating regression
oracles execute on exact-source hosted CI, and the claimed mechanical reduction has
checkable complexity/ownership/counter evidence. Green ordinary tests alone do not
prove elimination of repeated work; source changes alone do not prove executable
correctness. No local Cargo/npm is used. Root owns hosted runs and integration.

State vocabulary: **verified prior** = exact prior implementation/evidence only;
**implemented / review pending** = present source, not passing hosted acceptance;
**review issue** = concrete unresolved defect; **decision pending** = a trade-off
must be justified, not silently omitted. Unnecessary maximum-ID indexing, skipped
persistent validation, weaker canonical ZIP or lower durability are unacceptable
ways to close a row.

## Root-adjudicated M20 validation/fact scope (authoritative)

Eager regex engine work is required for ALL patterns inside a REFERENCED unit,
including uncalled macro bodies, because structural IR validation alone does not
check engine grammar and old middle specialization rejects invalid pools there.
It is NOT required for unreferenced archived IR. Old archived Compile paths
validate structural unit IR but do not compile its engine; old StaticLinker only
specializes reachable units. The remediation must not introduce engine validation
for an otherwise unreferenced archive module by constructing PreparedUnit too early.

Local frontend behavior is separate: it validates regex syntax throughout local
source units under the established language boundary. Archive reader still validates
complete structural/source/resource/binding authority at acquisition, even when
only some units are later scheduled. Manager must prune unreferenced archive units
before PreparedUnit construction/compile scheduling, then retain one immutable
PreparedUnit per relevant exact object and reuse facts across independent target/
include symbol scopes. Bindings remain per scope, not globally cached by macro name.

Required tests/work counts: malformed unused pattern in a referenced unit rejects;
unreferenced archive unit does not gain a new engine rejection; one shared referenced
module prepared once across N includes/targets; exact bytes/provenance and source
attachment authority remain checked. A blanket claim that every archived regex is
engine-validated is incorrect and is not this ledger's acceptance contract.

### M17 bounded concurrent acquisition / R07 test-hang issue

Source review of `crates/squish-store/src/session.rs`: the weak active-flight
registry is capped at 256, uses one Condvar per digest, and performs real CAS I/O
outside the global state mutex. Complete results/errors are published after real
verification/retention. FlightLeader drop publishes Interrupted and wakes waiters;
wait loops handle spurious wakes. Completed flight payload survives only while
actual overlapping callers retain the Flight, not via the weak registry. Distinct
new reads bypass coordination explicitly when saturated. Missing/corrupt results
are transient overlapping outcomes, not persistent negative cache entries. Runtime
construction resets CasSession for each host invocation; mutable source/generation
acquisition must not borrow this CAS snapshot trust.

R07 (test-only concrete hang risk, owner notified): the oversized eight-reader
zero-retention fixture waits at a reusable `before_read` Barrier. After its ten-second
coalescing deadline, main releases the gate once then joins all workers. A late worker
can become a SECOND leader after the first completed flight expires, wait at the
same gate, and hang forever because main never releases a second generation. Make
the gate single-use or clear it before releasing so a late reader fails work-count
assertions rather than hanging hosted CI. Existing drop-before-wait test checks
completed error identity, not an actually blocked waiter's wake; a synchronized
blocked-waiter regression is desirable bounded evidence. No production deadlock
was established by this test-harness finding.

R07 follow-up source resolution: the fixture `before_read` gate now uses
`Option::take()` once, so a late acquisition cannot encounter an unpaired second
Barrier generation. An additional synchronized `interrupted_leader_wakes_an_actually_blocked_reader`
uses cfg(test)-only wait evidence and always drops leader/joins before asserting
its deadline observation. Re-read both paths; concrete test-hang risk is corrected
at source. Hosted execution remains pending, not inferred from this inspection.
