## Expected-contract basis

The requested full remediation must improve ownership, graph identity and
verification mechanisms without weakening portable library semantics, derived
cache corruption detection, resource budgets or atomic public publication.
`docs/design/v1.2-archives.md` establishes shared asset ownership, schema-1 reader
compatibility and SCC-based source identity; `docs/design/v1.2-verified-runtime.md`
and `docs/performance/invocation-verified-storage.md` explicitly require new
invocations to verify durable bytes again. Existing compiler semantics require
import cycles to terminate source discovery, while recursive macro execution is
budgeted. Inputs and independently asserted output bytes are handwritten fixtures,
not obtained from the implementation under test.

## Measured work versus interpretation

The large-library fixture counts actual `action_queued` events whose kind is
`compile` in the process JSON protocol. This measures scheduled work, not
frontend parse calls, archive decode count or runtime latency. Its proposed
ceiling of two actions corresponds to one local pack and one imported archive
module. Root confirmed this remediation requirement: unrelated precompiled archive
objects must not be scheduled as compile/encode work, while complete archive
validation still occurs at reader acquisition. The numerical assertion must not
be relaxed merely to make current code pass. Malformed local units remain subject
to their established validation boundary.

Host archive-read/decode counters are test-only (`cfg(test)`); root chose the real
host/session counter tests as authoritative decode/hash mechanism evidence rather
than adding a new production CLI telemetry metric. Thus no process-level
decode-count claim is made. Unit counters complement the consumer process fixture,
whose protocol count measures actual scheduled compile work only.

## Legacy compatibility reference

An old-writer/new-reader process test must consume a frozen library generated
by shipped v1.2.0, not regenerate expected bytes with the candidate writer.
The candidate intentionally evolves provider-identity spelling; the compatibility
contract is continued reading and expansion, not equality to an old fingerprint.
Root delegated generation of the small legacy reference to the hosted CI/perf
owner before candidate compilation. The mandatory process test reads
`tests/fixtures/v1.2.0-library.sopack` (or explicit
`XMLSQUISH_LEGACY_SOPACK_FIXTURE` path) and fails clearly if absent, rather than
silently skipping compatibility. The fixture must export root macro `m:bundle`
in `urn:test:legacy-library`; it calls a foreign provider whose macro emits
`legacy.bin` containing exact `legacy\0\xffprovider` bytes. At least one archive
member must retain the released `_providers/` namespace. Archive bytes and
generation provenance must be preserved. Until that fixture is generated and
the hosted test runs, this path is **unverified**, not implicitly passed.
