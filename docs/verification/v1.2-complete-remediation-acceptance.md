## Expected-contract basis

verification mechanisms without weakening portable library semantics, derived
cache corruption detection, resource budgets or atomic public publication.

and `docs/performance/invocation-verified-storage.md` explicitly require new
invocations to verify durable bytes again. Existing compiler semantics require
import cycles to terminate source discovery, while recursive macro execution is
budgeted. Inputs and independently asserted output bytes are handwritten fixtures,
not obtained from the implementation under test.

## Measured work versus interpretation

The large-library fixture counts actual native-v3 `action_declared` events whose kind is
`compile` in the process JSON protocol. This measures scheduled work, not
frontend parse calls, archive decode count or runtime latency. Its proposed
ceiling of two actions corresponds to one local pack and one imported archive
module. Root confirmed this remediation requirement: unrelated precompiled archive
objects must not be scheduled as compile/encode work, while complete archive
validation still occurs at reader acquisition. The numerical assertion must not
be relaxed merely to make current code pass. Malformed local units remain subject
to their established validation boundary.

Host archive-read/decode counters are test-only (`cfg(test)`); root chose the real
host/session counter tests as authoritative decode/hash mechanism evidence rather
than adding a new production CLI telemetry metric. Thus no process-level
decode-count claim is made. Unit counters complement the consumer process fixture,
whose protocol count measures actual scheduled compile work only.

## Broader source-diagnostic regression boundary

After the RUN013 provenance gap, a ninth process fixture now covers duplicate
symbols at the linker boundary. Each library is built independently and is valid;
only importing both into one consumer closure is invalid. Both declare
`{urn:test:collision}shared` in `src/lib.xml`, but have distinct package identities,
source content and asset bytes. Producer trees are deleted before consumer linking.
The test requires established manager `diagnostic.code == "MGB070"` with compiler
cause `LNK023` retained in message/help, a structured primary source
containing relocated SOPack identity and `lib.xml`, and the expanded QName in
message/help. It deliberately does not hardcode an opaque URI scheme, content
fingerprint, source-registration order or device-absolute path. A legitimate
collision must not silently override a symbol or replace the prior public pack.

The pre-existing malformed-local-unit fixture additionally checks that frontend
diagnostic primary points to `uncalled.xml` and has `0 <= start < end <= source
byte length`. A message mentioning a filename, a null primary or a synthetic
zero-length placeholder no longer suffices for this frontend error. These new
assertions exercise boxed/typed diagnostic propagation through real host and
manager APIs; they are authored and format-checked, not yet executed in CI.

Root's final public-code policy preserves established manager terminal
`ActionFailed` / `WorkerFailure` codes (`MGB070` for normal linking and `MGB162`
for include linking), rather than replacing public machine codes with compiler
codes. The runtime API can retain the complete original boxed compiler diagnostic
internally; manager wrapping must preserve its source/span, related locations,
help and explicit compiler cause while keeping that external domain code. The
duplicate-provider fixture follows this compatibility contract without relaxing
any provenance or expanded-QName requirement.
